Теорія

Наскрізний приклад — дані каталогу книжок: масив об'єктів із назвою, автором, жанром, роком, кількістю сторінок, рейтингом і ціною. Цього разу ми не виводимо їх на сторінку (це тема наступної лекції про DOM), а вчимося зберігати, перевіряти, перетворювати й рахувати.

JavaScript у браузері: що це і як підключити

HTML описує, що є на сторінці, CSS — як воно виглядає. Але відфільтрувати каталог за жанром, порахувати суму кошика чи перевірити форму до відправки статична розмітка не може. Для цього потрібна мова програмування, яку браузер виконує сам, без встановлення додаткових програм.

Такою мовою є JavaScript, реалізація стандарту ECMAScript, з яким ви познайомилися в лекції 2. Браузер має рушій (V8 у Chrome й Edge, SpiderMonkey у Firefox, JavaScriptCore у Safari). Він розбирає код, компілює його на льоту й виконує. Важливо розрізняти саму мову і середовище. Змінні, функції, масиви, об'єкти й модулі — це ECMAScript, вони однакові в браузері й у Node.js. document, console, fetch — це API середовища. У цій лекції ми працюємо з мовою, а з console — лише щоб бачити результати.

Підключають код зовнішнім файлом. Як ви вже знаєте з лекції 1, класичний <script> без атрибутів зупиняє розбір HTML, тому для сучасного коду є два варіанти. defer завантажує скрипт паралельно й виконує після побудови DOM. type="module" робить файл ES-модулем, і це варіант за замовчуванням у нашому курсі. Модуль теж відкладений, має власну область видимості замість глобальної, завжди працює в суворому режимі й уміє імпортувати інші модулі. Для модулів потрібен локальний сервер, а не file://.

<script type="module" src="js/app.js"></script>

Суворий режим (strict mode) — варіант мови, у якому частину тихих помилок перетворено на явні. Присвоєння неоголошеній змінній кидає помилку замість того, щоб мовчки створити глобальну змінну. Заборонено дублікати імен параметрів. this у звичайній функції не підміняється глобальним об'єктом. Модулі й класи завжди суворі, а у класичному скрипті режим вмикає рядок "use strict"; на початку файлу.

Коли це знадобиться. З першого рядка коду: підключайте скрипти як модулі, тримайте відкритою консоль DevTools і пам'ятайте, які речі належать мові, а які — браузеру. Це полегшить і читання документації, і перехід до TypeScript та Node.js.

Змінні: let, const і чому не var

Програмі потрібно пам'ятати проміжні значення: введений пошуковий запит, поточну сторінку, знайдену книжку. Змінна — це ім'я, прив'язане до значення. Сучасний JavaScript має два способи її оголосити, і вибір між ними — не стиль, а повідомлення читачеві коду.

const оголошує прив'язку, яку не можна перепризначити. let — прив'язку, значення якої зміниться (лічильник циклу, накопичувач). Обидва мають блокову область видимості: змінна існує лише всередині фігурних дужок, де її оголошено. Якщо оголосити const без значення або присвоїти їй нове значення, отримаєте помилку ще до виконання логіки.

Найпоширеніше непорозуміння: const забороняє перепризначення змінної, а не зміну значення. Якщо в const лежить об'єкт чи масив, сам об'єкт змінювати можна: додавати властивості, викликати push. Не можна лише змусити змінну вказувати на інший об'єкт.

const MAX_PAGE_SIZE = 50;     // a named constant instead of a "magic number"
let currentPage = 1;          // will change
currentPage += 1;             // OK

const book = { title: "CSS in Depth", year: 2024 };
book.year = 2025;             // OK: the object changes, the binding does not
// book = {};                 // TypeError: Assignment to constant variable.

var — спосіб із перших версій мови, і має він три вади. Його область видимості — уся функція, а не блок, тож змінна «протікає» з циклу чи if. Оголошення піднімається на початок функції зі значенням undefined, тож звернення до змінної до її оголошення не дає помилки, а тихо повертає undefined. На верхньому рівні класичного скрипта var ще й створює властивість глобального об'єкта window, яку може перезаписати будь-який інший скрипт. У новому коді var не використовують, але ви зустрінете його в старих прикладах і бібліотеках.

Імена змінних пишуть у camelCase: currentPage, filteredBooks. Ім'я має казати, що в змінній, а не якого вона типу: books, а не arr. Булеві значення починають з is, has, can: isInStock, hasDiscount. Сталі на рівні модуля, як-от MAX_PAGE_SIZE, часто пишуть великими літерами.

Коли це знадобиться. У кожному рядку. Правило просте: пишіть const, а на let переходьте лише тоді, коли значення справді треба перепризначити. Тоді кожне let у коді сигналізує: «тут щось змінюється, будь уважним».

Типи даних і typeof

JavaScript — мова з динамічною типізацією: тип має значення, а не змінна. Та сама змінна let може містити спершу число, а потім рядок. Це гнучко, але без розуміння типів не передбачити, що зробить + чи порівняння. Тому спершу — що за типи існують.

Є сім примітивних типів. string — текст у лапках чи зворотних апострофах. number — усі числа, і цілі, і дробові. bigint — цілі довільної величини з суфіксом n. boolean — true чи false. undefined — «значення не задано». null — «значення навмисно порожнє». symbol — унікальний ідентифікатор. Усе інше — об'єкти: звичайні об'єкти, масиви, функції, дати, Map, Set. Примітиви незмінні й порівнюються за значенням. Об'єкти зберігаються за посиланням: дві змінні можуть вказувати на той самий об'єкт, а два однакові на вигляд об'єкти не рівні між собою.

console.log(typeof "CSS");        // "string"
console.log(typeof 42);           // "number"
console.log(typeof 10n);          // "bigint"
console.log(typeof undefined);    // "undefined"
console.log(typeof null);         // "object" — a bug from 1995 kept for compatibility
console.log(typeof [1, 2]);       // "object" — use Array.isArray to detect arrays
console.log(typeof (() => {}));   // "function"

console.log(Array.isArray([1, 2]));               // true
console.log({ id: 1 } === { id: 1 });             // false: two different objects
const sameBook = { id: 1 };
const alias = sameBook;
console.log(alias === sameBook);                  // true: one object, two names

Числа зберігаються у 64-бітному форматі з рухомою комою IEEE 754, як double у Java чи C. Звідси три наслідки. Дроби, що в двійковій системі нескінченні, округлюються, тому 0.1 + 0.2 дорівнює 0.30000000000000004: гроші рахують у копійках цілими числами, а дробові результати порівнюють з допуском. Цілі числа точні лише до Number.MAX_SAFE_INTEGER (2⁵³ − 1), далі потрібен bigint. І є особливі значення: Infinity і NaN («не число», результат "abc" * 2). NaN не дорівнює навіть самому собі, тому перевіряють його через Number.isNaN(value).

Рядки незмінні: методи trim, toUpperCase, slice, replaceAll повертають новий рядок, а не змінюють старий. Шаблонні рядки у зворотних апострофах підставляють вирази через ${} і можуть бути багаторядковими.

function formatPrice(priceInCents) {
  return `${(priceInCents / 100).toFixed(2)} грн`;
}

const query = "  Eloquent JavaScript ";
console.log(query.trim().toLowerCase());  // "eloquent javascript"
console.log(formatPrice(129950));         // "1299.50 грн"
console.log(Number.isNaN(Number("abc"))); // true

Коли це знадобиться. Щоразу, коли дані приходять ззовні — з поля форми чи з API. Значення поля введення завжди рядок, навіть якщо там «42». Розуміння типів — основа і для наступного розділу, і для TypeScript, який зробить типи явними.

Приведення типів: явне і неявне, == проти ===

Користувач ввів у поле «Кількість» значення 3, код додає до нього 1 і отримує "31". Причина в тому, що значення поля — рядок, а + з рядком означає склеювання. Коли операція отримує значення не того типу, JavaScript не кидає помилку, а неявно перетворює його за правилами специфікації. Правила детерміновані, і їх можна вивчити. Але надійніше перетворювати явно.

Явне приведення робиться функціями Number(value), String(value) і Boolean(value). Number("42") дає 42, Number("") — 0, Number("4 2") — NaN. parseInt("42px", 10) читає цифри з початку рядка й зупиняється на першій нецифрі. До хибних (falsy) значень у логічному контексті належать рівно вісім: false, 0, -0, 0n, "", null, undefined і NaN. Усе інше істинне (truthy), включно з "0", "false", порожнім масивом [] і порожнім об'єктом {}.

Неявне приведення найчастіше трапляється в трьох місцях. Оператор + спершу перетворює об'єкти на примітиви. Якщо хоч один з операндів рядок, він склеює рядки, інакше додає числа. Тому "5" + 3 дає "53", а [] + [] — порожній рядок. Решта арифметичних операторів (-, *, /, %) завжди перетворюють операнди на числа, тож "5" - 3 дає 2. Оператори порівняння < і > порівнюють два рядки посимвольно ("10" < "9" — true), а в інших випадках перетворюють на числа.

Нестроге порівняння == намагається привести операнди до спільного типу. null і undefined рівні лише одне одному. Число й рядок порівнюються як числа. Булеве значення спершу стає числом (true → 1). Об'єкт перетворюється на примітив. Тому [] == false дає true: false стає 0, [] — порожнім рядком, а той — нулем. Строге порівняння === нічого не перетворює: різні типи означають «не рівні». Його й використовують завжди. Для двох рідкісних випадків є Object.is: він вважає NaN рівним NaN і розрізняє 0 та -0.

function parseQuantity(rawValue) {
  const quantity = Number(rawValue.trim());
  return Number.isInteger(quantity) && quantity > 0 ? quantity : null;
}

console.log("3" + 1);                // "31" — concatenation
console.log(parseQuantity("3") + 1); // 4    — explicit conversion first
console.log(parseQuantity("abc"));   // null
console.log(0 == "");                // true  — both become 0
console.log(0 === "");               // false — different types
console.log(null == undefined);      // true
console.log(null === undefined);     // false

Коли це знадобиться. Під час роботи з будь-якими даними від користувача чи сервера. Перетворіть значення явно на вході, порівнюйте через ===, і неявне приведення майже зникне з вашого коду. Побачити покроково, як працює кожен оператор, можна у візуалізаторі приведення.

Оператори й умови

Програма постійно обчислює й вирішує: яка ціна зі знижкою, чи є книжка в наявності, яку позначку показати. Для обчислень є оператори, для рішень — умовні конструкції.

Арифметичні оператори: + - * /, остача % (зручна для перевірки парності, n % 2 === 0) і степінь **. Скорочене присвоєння +=, -=, *= та інкремент ++ змінюють значення змінної. Порівняння: ===, !==, <, >, <=, >=.

Логічні оператори &&, || і ! в JavaScript особливі. && і || повертають не true чи false, а один з операндів, і обчислюються за короткою схемою. a && b повертає a, якщо воно хибне, інакше b. a || b повертає a, якщо воно істинне, інакше b. Правий операнд обчислюється лише тоді, коли потрібен. Звідси популярний запис значення за замовчуванням pageSize || 20 і його пастка: 0 і порожній рядок теж хибні. Для «за замовчуванням» правильний оператор — ?? (nullish coalescing). Він підставляє праве значення лише для null та undefined, тож 0 ?? 20 дає 0. ?. (optional chaining) звертається до властивості лише тоді, коли ліва частина не null чи undefined, інакше повертає undefined замість TypeError.

const settings = { pageSize: 0, theme: "" };
console.log(settings.pageSize || 20); // 20 — 0 is falsy, the user's choice is lost
console.log(settings.pageSize ?? 20); // 0  — only null/undefined are replaced

const book = { title: "CSS in Depth", author: null };
console.log(book.author?.name ?? "Unknown author"); // "Unknown author"

Умовні конструкції. if / else if / else виконує одну з гілок за умовою, яка перетворюється на boolean. Тернарний оператор умова ? a : b — вираз, а не інструкція: він повертає значення, тож годиться для вибору значення, а не для запуску дій. switch порівнює значення з кількома варіантами через ===. Без break виконання «провалюється» в наступний case, і це часте джерело помилок. Якщо кожен case лише повертає значення, зручніше використати об'єкт-словник.

Глибока вкладеність if робить код нечитабельним. Прийом раннього повернення (guard clause) спершу відсікає некоректні випадки через return, і основна логіка йде без зайвих відступів.

const DISCOUNT_BY_LEVEL = { bronze: 0.05, silver: 0.1, gold: 0.15 };

function getDiscountRate(level) {
  return DISCOUNT_BY_LEVEL[level] ?? 0;
}

function getPriceWithDiscount(priceInCents, level) {
  if (!Number.isInteger(priceInCents) || priceInCents < 0) {
    return null;                        // guard clause: reject bad input early
  }
  const rate = getDiscountRate(level);
  return Math.round(priceInCents * (1 - rate));
}

function getStockLabel(count) {
  return count > 0 ? `В наявності: ${count}` : "Немає в наявності";
}

console.log(getPriceWithDiscount(50000, "silver")); // 45000
console.log(getPriceWithDiscount(-1, "gold"));      // null
console.log(getStockLabel(0));                      // "Немає в наявності"

Коли це знадобиться. У кожній функції, що приймає рішення. ?? — для значень за замовчуванням, ?. — для даних, де поле може бути відсутнім, ранній return — замість драбини вкладених if.

Цикли

Порахувати книжки кожного жанру, знайти першу недоступну, повторювати спробу, доки не вийде, — усе це повторення дій. JavaScript має кілька видів циклів, і кожен підходить для свого.

Класичний for (let i = 0; i < n; i++) дає повний контроль над лічильником: крок, напрямок, межу. while повторює, доки умова істинна, і годиться, коли кількість ітерацій наперед невідома. do...while перевіряє умову після першого виконання. break перериває цикл, continue переходить до наступної ітерації.

for...of перебирає значення будь-якої ітерованої колекції: масиву, рядка, Map, Set. Це найчитабельніший цикл для колекцій. for...in перебирає ключі об'єкта, включно з успадкованими перелічуваними, тож для масивів він не годиться. Для об'єктів зручніше for (const [key, value] of Object.entries(object)).

const genres = ["css", "js", "css", "html", "js", "css"];

function countByValue(values) {
  const counts = {};
  for (const value of values) {
    counts[value] = (counts[value] ?? 0) + 1;
  }
  return counts;
}

function findFirstIndexOver(numbers, limit) {
  for (let i = 0; i < numbers.length; i++) {
    if (numbers[i] > limit) return i;  // exit as soon as the answer is known
  }
  return -1;
}

const counts = countByValue(genres);
console.log(counts);                                  // { css: 3, js: 2, html: 1 }
for (const [genre, count] of Object.entries(counts)) {
  console.log(`${genre}: ${count}`);
}
console.log(findFirstIndexOver([120, 340, 610, 280], 500)); // 2

Для типових операцій над масивами — перетворити, відфільтрувати, знайти, порахувати — замість циклу зазвичай беруть методи масивів. Вони коротші й прямо називають намір. Цикл лишається, коли потрібен ранній вихід зі складною логікою, коли ітеруються не масиви або коли важлива продуктивність на великих даних.

Коли це знадобиться. У підрахунках і пошуку. За замовчуванням обирайте for...of для колекцій і методи масивів для перетворень, а for...in лишайте для рідкісних випадків з об'єктами.

Функції: оголошення, вирази, стрілкові

Розрахунок ціни зі знижкою потрібен у картці, у кошику й у підсумку замовлення. Якщо скопіювати формулу тричі, виправляти помилку доведеться тричі. Функція дає іменований шматок логіки, який приймає вхідні дані (параметри) і повертає результат через return. Без return функція повертає undefined.

Є три форми запису. Оголошення функції function name() {} піднімається повністю, тож його можна викликати вище за текстом файлу. Функціональний вираз const name = function () {} — це значення, присвоєне змінній, і доступне воно лише після рядка присвоєння. Стрілкова функція const name = (a, b) => a + b має найкоротший запис. Якщо тіло — один вираз без фігурних дужок, його значення повертається автоматично. З фігурними дужками потрібен явний return, а об'єкт у короткій формі беруть у круглі дужки: () => ({ id: 1 }). Крім того, стрілкові функції не мають власних this і arguments, про що йтиметься в розділі про об'єкти.

Параметри можуть мати значення за замовчуванням: function paginate(items, page = 1, size = 10). Rest-параметр ...values збирає довільну кількість аргументів у масив. Функції — це значення: їх можна зберігати в змінних, передавати як аргументи й повертати з інших функцій. Функцію, передану іншій функції, називають колбеком, і на цьому побудовані методи масивів.

function getAverage(...values) {           // declaration + rest parameter
  if (values.length === 0) return 0;
  const sum = values.reduce((total, value) => total + value, 0);
  return sum / values.length;
}

const toUpperTitle = (title) => title.toUpperCase();   // arrow, implicit return
const createBook = (title, year = 2026) => ({ title, year }); // object needs ( )

function applyToAll(items, transform) {    // a function that takes a function
  return items.map(transform);
}

console.log(getAverage(4.5, 4.8, 4.1));        // 4.466666666666667
console.log(createBook("Learning Web Design")); // { title: "Learning Web Design", year: 2026 }
console.log(applyToAll(["css", "js"], toUpperTitle)); // ["CSS", "JS"]

Чиста функція повертає результат, що залежить лише від її параметрів, і нічого не змінює поза собою: не пише в глобальні змінні, не змінює переданий масив, не виводить у консоль. Такі функції легко перевірити, використати повторно й тестувати. Решта коду — виведення, запис, зміна сторінки — називається побічними ефектами. Їх збирають в окремі, якомога тонші функції. Саме тому в прикладах цієї лекції логіка живе у функціях, що повертають значення, а console.log стоїть лише в кінці, де результат виводять.

Коли це знадобиться. Завжди. Функція має робити одну річ, мати ім'я-дієслово (getAverage, formatPrice, isInStock) і повертати результат, а не виводити його. На такий код легко накласти тести в кінці курсу.

Область видимості, підняття і тимчасова мертва зона

Дві функції мають локальну змінну total. Чи заважають вони одна одній? Чи бачить вкладена функція змінні зовнішньої? Чому звернення до змінної «вище» за її оголошення інколи дає undefined, а інколи помилку? Відповіді дає правило області видимості.

Область видимості (scope) — частина коду, де ім'я доступне. Є глобальна область, область модуля (кожен модуль має власну), область функції та блокова область всередині {} для let і const. Області вкладені, і JavaScript використовує лексичну видимість: функція бачить змінні областей, у яких вона написана, а не тих, звідки її викликали. Внутрішнє оголошення з тим самим ім'ям затінює зовнішнє.

Функція «пам'ятає» область, у якій її створено, навіть після того, як зовнішня функція завершилася. Таку комбінацію функції та її області називають замиканням (closure). Так зберігають приватний стан без глобальних змінних.

function createIdGenerator(prefix) {
  let lastId = 0;                    // private state, invisible outside
  return () => {
    lastId += 1;
    return `${prefix}-${lastId}`;
  };
}

const nextBookId = createIdGenerator("book");
console.log(nextBookId()); // "book-1"
console.log(nextBookId()); // "book-2"
// console.log(lastId);    // ReferenceError: lastId is not defined

Підняття (hoisting). Перед виконанням області рушій реєструє всі її оголошення, але по-різному. Оголошення функції піднімається повністю, разом із тілом. var піднімається зі значенням undefined. let, const і class теж реєструються, але до рядка оголошення перебувають у тимчасовій мертвій зоні (temporal dead zone, TDZ): будь-яке звернення кидає ReferenceError. Це не обмеження, а захист. Помилка видна одразу, а не перетворюється на тихе undefined десь далі в логіці.

console.log(describe("CSS")); // works: a function declaration is fully hoisted

function describe(title) {
  return `Book: ${title}`;
}

try {
  console.log(pageSize);      // TDZ: the binding exists but is not initialized yet
  const pageSize = 20;
} catch (error) {
  console.log(error.name);    // "ReferenceError"
}

Коли це знадобиться. Коли бачите ReferenceError чи undefined там, де не очікували, і щоразу, коли хочеться «зробити змінну глобальною, щоб усі бачили». Майже завжди замість цього потрібен параметр функції, повернене значення або модуль.

Об'єкти: властивості, методи, базове розуміння this

Книжка — це не одне значення, а набір пов'язаних: назва, автор, рік, ціна. Тримати їх у п'яти окремих змінних незручно, і зв'язок між ними губиться. Об'єкт збирає пов'язані значення під іменами-ключами.

Об'єкт створюють літералом у фігурних дужках. До властивостей звертаються через крапку (book.title) або квадратні дужки (book[key]), коли ім'я властивості лежить у змінній чи містить символи, недопустимі в ідентифікаторі. Неіснуюча властивість дає undefined, а не помилку. Властивості можна додавати, змінювати й видаляти через delete. Перевірити наявність дозволяють оператор in і Object.hasOwn(object, key). Object.keys, Object.values і Object.entries повертають масиви ключів, значень і пар. Скорочений запис { title, year } бере значення зі змінних з такими самими іменами, а обчислюваний ключ { [key]: value } — з виразу.

Функцію, що лежить у властивості, називають методом. Усередині методу ключове слово this вказує на об'єкт, «зліва від крапки» під час виклику: у cart.getTotal() це cart. this визначається тим, як функцію викликали, а не де її написали. Тому метод, переданий як колбек окремо від об'єкта, втрачає this. Стрілкові функції власного this не мають і беруть його з навколишньої області, тож методами об'єктів їх не роблять. Зате всередині методу стрілкові колбеки зручні саме тим, що «бачать» this методу.

const cart = {
  items: [
    { title: "CSS in Depth", priceInCents: 129900, quantity: 1 },
    { title: "HTML and CSS", priceInCents: 89900, quantity: 2 },
  ],
  getTotal() {                                   // method shorthand
    return this.items.reduce(
      (sum, item) => sum + item.priceInCents * item.quantity, // arrow sees the method's this
      0,
    );
  },
};

const field = "title";
console.log(cart.items[0][field]);          // "CSS in Depth"
console.log(cart.getTotal());               // 309700
console.log(Object.keys(cart.items[1]));    // ["title", "priceInCents", "quantity"]
console.log("discount" in cart);            // false

const getTotal = cart.getTotal;
// getTotal();  // TypeError: this is undefined in strict mode — the method lost its object

Об'єкти, як і масиви, передаються за посиланням. Функція, що отримала об'єкт і змінила його властивість, змінила об'єкт і для всіх, хто на нього посилається. Object.freeze(object) забороняє зміни, але лише на першому рівні вкладеності. Здебільшого простіше домовитися не змінювати вхідні дані, а повертати нові об'єкти.

Коли це знадобиться. Кожна сутність каталогу — книжка, фільтр, налаштування, кошик — це об'єкт. Глибше this і класи розглядатимуться разом із TypeScript, а поки досить двох правил: методи пишіть скорочено, а стрілкові функції використовуйте як колбеки.

Масиви й методи перебору

Каталог — це впорядкована колекція книжок, і з нею постійно щось роблять: показують лише CSS-книжки, сортують за роком, рахують середній рейтинг, шукають за id. Писати для кожної дії окремий цикл з тимчасовими змінними — довго, а наміру за кодом не видно. Масиви мають методи, назва кожного з яких і є намір.

Основи. Індекси починаються з 0, length — кількість елементів, at(-1) — останній. push, pop, shift, unshift і splice змінюють масив на місці. slice, concat і spread створюють новий. includes перевіряє наявність значення, indexOf повертає його позицію.

Методи перебору приймають колбек і викликають його для кожного елемента. map перетворює кожен елемент і повертає новий масив тієї самої довжини. filter відбирає елементи, для яких колбек повернув істинне значення. find і findIndex шукають перший відповідний елемент чи його індекс, findLast — останній. some і every перевіряють, чи підходить хоч один чи всі. reduce згортає масив в одне значення через накопичувач. Йому варто завжди давати початкове значення, бо на порожньому масиві без нього він кидає TypeError. forEach нічого не повертає й призначений лише для побічних ефектів.

Сортування. sort змінює масив на місці, а без функції порівняння сортує як рядки: [10, 9, 1, 100].sort() дає [1, 10, 100, 9]. Функція порівняння повертає від'ємне число, якщо a має йти раніше, додатне — якщо пізніше, і нуль, якщо порядок не важливий. Для чисел це (a, b) => a - b, для рядків — a.localeCompare(b, "uk"), що правильно впорядковує літери «є», «і», «ї». З ES2023 є методи, що не змінюють оригінал: toSorted, toReversed, toSpliced і with(index, value). Групувати можна через Object.groupBy(items, callback) з ES2024.

const books = [
  { id: 1, title: "CSS in Depth", genre: "css", year: 2024, rating: 4.6, pages: 472 },
  { id: 2, title: "Eloquent JavaScript", genre: "js", year: 2024, rating: 4.8, pages: 456 },
  { id: 3, title: "HTML and CSS", genre: "html", year: 2011, rating: 4.4, pages: 512 },
  { id: 4, title: "You Don't Know JS Yet", genre: "js", year: 2020, rating: 4.5, pages: 143 },
];

function getTitlesByGenre(items, genre) {
  return items
    .filter((book) => book.genre === genre)          // select
    .toSorted((a, b) => b.year - a.year)             // order, without mutating
    .map((book) => book.title);                      // transform
}

function getAverageRating(items) {
  if (items.length === 0) return 0;
  const sum = items.reduce((total, book) => total + book.rating, 0); // initial value!
  return Math.round((sum / items.length) * 100) / 100;
}

console.log(getTitlesByGenre(books, "js"));       // ["Eloquent JavaScript", "You Don't Know JS Yet"]
console.log(getAverageRating(books));             // 4.57 (4.575 is stored as 4.57499…)
console.log(books.find((book) => book.id === 3)?.title); // "HTML and CSS"
console.log(books.some((book) => book.pages < 200));     // true
console.log(books.every((book) => book.rating >= 4.5));  // false
console.log(Object.groupBy(books, (book) => book.genre).js.length); // 2

Метод обирають за наміром. Потрібен масив того самого розміру — map. Менший масив — filter. Один елемент — find. Так чи ні — some або every. Одне число чи об'єкт — reduce. Ланцюжки читаються зверху вниз як опис кроків, а проміжні результати не потрібно зберігати у змінних. Кожен крок ланцюжка можна побачити окремо в конвеєрі методів масиву.

Коли це знадобиться. У лабораторних про обробку колекцій каталогу: пошук, фільтрація, сортування, статистика. Правило безпеки: метод, що змінює масив (sort, reverse, splice), не застосовують до вхідних даних функції. Беруть його аналог із to.

Деструктуризація, spread і rest

Функція отримує книжку, а потрібні їй лише назва й рік. Запис book.title і book.year у кожному рядку робить код довгим і ховає, від яких полів функція насправді залежить. Інша типова задача — створити змінену копію об'єкта чи об'єднати два масиви, не чіпаючи оригіналів.

Деструктуризація розбирає об'єкт або масив на змінні одним рядком. Для об'єктів працює за іменами: const { title, year } = book. Можна перейменувати змінну ({ title: bookTitle }), задати значення за замовчуванням ({ rating = 0 }) чи розібрати вкладений об'єкт. Для масивів деструктуризація працює за позицією: const [first, second] = items. Найкорисніше застосування — деструктуризація параметрів. Сигнатура функції прямо показує, які поля вона використовує, а виклик з об'єктом опцій не залежить від порядку аргументів.

Spread ... «розгортає» масив чи об'єкт: [...a, ...b] об'єднує масиви, { ...book, year: 2026 } створює копію з одним зміненим полем. Пізніші властивості перезаписують раніші. Rest записується тими самими трьома крапками, але збирає решту: const { id, ...data } = book відокремлює id від інших полів. Різниця лише в позиції: справа від = чи в аргументах виклику — spread, зліва чи в параметрах — rest.

function formatBookLine({ title, year, author = "Unknown author" }) {
  return `${title} (${year}) — ${author}`;
}

function withUpdatedYear(book, year) {
  return { ...book, year };                 // a new object, the original is untouched
}

const book = { id: 7, title: "Learning Web Design", year: 2018 };
const { id, ...bookData } = book;           // rest: everything except id
const [first, ...others] = ["css", "js", "html"];

console.log(formatBookLine(book));          // "Learning Web Design (2018) — Unknown author"
console.log(withUpdatedYear(book, 2026).year, book.year); // 2026 2018
console.log(id, bookData);                  // 7 { title: "Learning Web Design", year: 2018 }
console.log(first, others);                 // "css" ["js", "html"]

Коли це знадобиться. У параметрах функцій, що приймають об'єкти даних, в оновленнях стану без мутацій і в роботі з відповідями API, де з великого об'єкта потрібні два поля.

Копіювання і JSON

Ви «скопіювали» книжку, щоб відредагувати назву в чернетці, а змінилася й книжка в каталозі. Причина в тому, що присвоєння об'єкта копіює посилання, а не сам об'єкт. Навіть справжня копія буває двох видів.

Поверхнева копія ({ ...object }, [...array], Array.from, slice) створює новий об'єкт першого рівня. Вкладені об'єкти й масиви лишаються спільними з оригіналом, і зміна copy.tags.push(...) змінить original.tags. Глибоку копію робить вбудована функція structuredClone(value). Вона рекурсивно копіює об'єкти, масиви, дати, Map, Set і навіть циклічні посилання, але не копіює функції та DOM-вузли (кидає помилку). Старий прийом JSON.parse(JSON.stringify(value)) губить undefined, функції, Map і перетворює дати на рядки, тому для копіювання його не використовують.

const original = { title: "CSS in Depth", tags: ["layout"] };

const shallow = { ...original };
shallow.tags.push("grid");                     // the nested array is shared!
console.log(original.tags);                    // ["layout", "grid"]

const deep = structuredClone(original);
deep.tags.push("flexbox");
console.log(original.tags.length, deep.tags.length); // 2 3

JSON (JavaScript Object Notation) — текстовий формат обміну даними, що походить від синтаксису літералів JavaScript, але суворіший. Ключі й рядки беруться лише в подвійні лапки, коментарів і кінцевих ком немає, а значеннями можуть бути лише рядки, числа, true, false, null, масиви й об'єкти. JSON.stringify(value, null, 2) перетворює значення на рядок з відступами: функції й undefined пропускаються, дата стає рядком ISO. JSON.parse(text) відновлює дані, а на некоректному тексті кидає SyntaxError. Тому дані з ненадійних джерел розбирають у try...catch. Саме в JSON сервер віддаватиме каталог у лекціях про API.

function parseBooks(text) {
  try {
    const data = JSON.parse(text);
    return Array.isArray(data) ? data : [];
  } catch {
    return [];                                 // a broken file must not break the app
  }
}

const json = JSON.stringify([{ id: 1, title: "CSS in Depth", published: new Date("2024-03-01") }]);
console.log(json);                   // [{"id":1,"title":"CSS in Depth","published":"2024-03-01T00:00:00.000Z"}]
console.log(parseBooks(json).length); // 1
console.log(parseBooks("{oops"));     // []

Коли це знадобиться. Щоразу, коли дані треба змінити, не чіпаючи оригіналу, зберегти в localStorage або отримати з сервера. Запитайте себе, чи є в об'єкті вкладені структури. Якщо так, поверхневої копії замало.

Модулі ESM

Коли весь код каталогу лежить в одному файлі на тисячу рядків, знайти потрібну функцію важко, а імена змінних різних частин конфліктують. Розбити код на кілька класичних скриптів — не вихід: усі вони ділять одну глобальну область, а порядок тегів <script> стає неявною залежністю, яку легко зламати.

ES-модулі (ECMAScript modules, ESM) розв'язують обидві проблеми. Кожен файл-модуль має власну область видимості. Назовні він віддає лише те, що позначено export, а потрібне іншим модулям явно бере через import. Залежності видно в коді, і браузер сам завантажує їх у правильному порядку. Модуль виконується один раз, навіть якщо його імпортують з десяти місць. Модулі завжди в суворому режимі та відкладені, як defer, а на верхньому рівні дозволяють await (ES2022).

Іменовані експорти (export function formatPrice) імпортують у фігурних дужках під тим самим ім'ям або з перейменуванням через as. Експорт за замовчуванням (export default) — один на модуль, і імпортують його під будь-яким іменем. Іменовані експорти зручніші: редактор підказує й перейменовує їх, а пошук за іменем знаходить усі використання. import * as utils збирає всі експорти в об'єкт. Динамічний import("./module.js") завантажує модуль на вимогу й повертає проміс.

// js/format.js
export const CURRENCY = "грн";

export function formatPrice(priceInCents) {
  return `${(priceInCents / 100).toFixed(2)} ${CURRENCY}`;
}

// js/catalog.js

  return books.filter((book) => book.genre === genre).map((book) => book.title);

І модулі завантажуються за правилами CORS, тож сторінку відкривають через локальний сервер, а не через file://.

Коли це знадобиться. З першої лабораторної на JavaScript: дані каталогу, функції обробки й виведення в окремих модулях. Ця сама структура без змін перейде в TypeScript і в проєкт на Vite.

Налагодження: повідомлення про помилки, console і DevTools

Код рідко працює з першого разу, і це нормально. Важливо не гадати, а швидко знаходити причину. Найчастіше браузер уже назвав її в повідомленні про помилку, тож навичка читати ці повідомлення важить більше за будь-який інструмент.

Повідомлення в консолі має тип, текст і місце. SyntaxError означає, що код не вдалося навіть розібрати: пропущена дужка, кома, лапка. Модуль з такою помилкою не виконається взагалі. ReferenceError — звернення до імені, якого немає або яке ще в TDZ, найчастіше через описку. TypeError — операція над значенням не того типу, класика: Cannot read properties of undefined (reading 'title'). Отже, зліва від .title опинилося undefined, і питання в тому, звідки воно там. RangeError — значення поза допустимим діапазоном, наприклад нескінченна рекурсія. Посилання праворуч, як-от catalog.js:14, відкриває потрібний рядок.

console.log показує значення, console.table — масив об'єктів таблицею, console.error і console.warn виділяють повідомлення, console.group групує пов'язаний вивід. Коли логів уже замало, ставлять точку зупинки в панелі Sources або пишуть інструкцію debugger;. Виконання зупиняється, і видно всі змінні в Scope, ланцюжок викликів у Call Stack, а кнопки Step over, Step into й Step out дають змогу виконувати код рядок за рядком. Розв'язана міні-задача: статистика каталогу

Умова. Є масив книжок каталогу з полями title, genre, year, rating, priceInCents та inStock. Потрібно сформувати звіт: скільки книжок кожного жанру; середній рейтинг книжок у наявності з округленням до двох знаків; найновіша книжка; загальна вартість книжок у наявності. Порожній каталог не має спричиняти помилок.

Як думати. Звіт складається з чотирьох незалежних обчислень, тож кожне стає окремою чистою функцією з іменем-дієсловом, що приймає масив і повертає значення. Відбір книжок у наявності потрібен двом обчисленням, тому це теж окрема функція. Форматування звіту — ще одна функція, яка лише збирає готові значення в рядки. Нарешті, main викликає функції й виводить результат. Це єдине місце з побічним ефектом. Кожен крок обираємо за наміром: підрахунок за ключем — reduce у новий об'єкт, відбір — filter, середнє й сума — reduce з початковим значенням, «найбільше за полем» — reduce, що порівнює. Сортувати весь масив заради одного елемента не потрібно.

const BOOKS = [
  { title: "CSS in Depth", genre: "css", year: 2024, rating: 4.6, priceInCents: 129900, inStock: true },
  { title: "Eloquent JavaScript", genre: "js", year: 2024, rating: 4.8, priceInCents: 99900, inStock: false },
  { title: "HTML and CSS", genre: "html", year: 2011, rating: 4.4, priceInCents: 89900, inStock: true },
  { title: "You Don't Know JS Yet", genre: "js", year: 2020, rating: 4.5, priceInCents: 59900, inStock: true },
  { title: "Semantic HTML in Practice", genre: "html", year: 2025, rating: 4.3, priceInCents: 149900, inStock: true },
];

function countByGenre(books) {
  return books.reduce((counts, book) => ({ ...counts, [book.genre]: (counts[book.genre] ?? 0) + 1 }), {});
}

function getInStock(books) {
  return books.filter((book) => book.inStock);
}

function getAverageRating(books) {
  if (books.length === 0) return 0;
  const sum = books.reduce((total, book) => total + book.rating, 0);
  return Math.round((sum / books.length) * 100) / 100;
}

function findNewest(books) {
  return books.reduce((newest, book) => (newest === null || book.year > newest.year ? book : newest), null);
}

function getTotalPrice(books) {
  return books.reduce((total, book) => total + book.priceInCents, 0);
}

function formatPrice(priceInCents) {
  return `${(priceInCents / 100).toFixed(2)} грн`;
}

function buildReport(books) {
  const inStock = getInStock(books);
  const newest = findNewest(books);
  return [
    `За жанрами: ${JSON.stringify(countByGenre(books))}`,
    `Середній рейтинг у наявності: ${getAverageRating(inStock)}`,
    `Найновіша: ${newest ? `${newest.title} (${newest.year})` : "—"}`,
    `Вартість у наявності: ${formatPrice(getTotalPrice(inStock))}`,
  ];
}

function main() {
  for (const line of buildReport(BOOKS)) console.log(line);
  console.log(buildReport([]).join(" | "));   // the empty catalog does not break
}

main();

Результат. Для наведених даних звіт виглядає так: жанри {"css":1,"js":2,"html":2}, середній рейтинг у наявності 4.45, найновіша — Semantic HTML in Practice (2025), вартість у наявності 4296.00 грн. Для порожнього каталогу: {}, 0, «—» і 0.00 грн. Кожну функцію можна перевірити окремо: у JS-консолі є цей код як готовий приклад. Спробуйте додати функцію «найдорожча книжка кожного жанру» в тому самому стилі.

Чому саме так. Маленькі чисті функції можна тестувати поодинці, використовувати повторно (getAverageRating працює для будь-якої вибірки) й читати без коментарів. Порожній масив обробляє кожна функція окремо, тому звіт не падає. Перетворити цей код на рендер у DOM у наступній лекції означатиме замінити лише main.

    function getNewest(books) {
  return books.sort((a, b) => b.year - a.year)[0];  // reorders the caller's catalog!
}
const newest = getNewest(catalog);
// catalog is now sorted by year, and the page shows a different order

    Чому це погано. sort, reverse і splice змінюють масив на місці, і зміна видна всім, хто тримає посилання на нього. Функція «лише знайти найновішу» непомітно змінює порядок каталогу на сторінці, і помилка проявляється в зовсім іншій частині програми.

    ✓ Добре 
    function getNewest(books) {
  return books.toSorted((a, b) => b.year - a.year)[0];
}
// even better: one pass, no sorting at all
const findNewest = (books) => books.reduce((top, book) => (!top || book.year > top.year ? book : top), null);

    || замість ?? для значень за замовчуванням

    ✗ Погано 
    const pageSize = settings.pageSize || 20;   // the user chose 0 → becomes 20
const note = book.note || "No note";        // the user saved "" on purpose → replaced
const discount = book.discount || 0.1;       // 0 (no discount) → 10% discount!

    Чому це погано. || замінює будь-яке хибне значення, а 0, "" і false — цілком легітимні дані. Найнебезпечніше це в грошах і налаштуваннях: «знижки немає» перетворюється на знижку за замовчуванням.

    ✓ Добре 
    const pageSize = settings.pageSize ?? 20;   // replaced only when null or undefined
const discount = book.discount ?? 0.1;

    Поверхнева копія там, де потрібна глибока

    ✗ Погано 
    const draft = { ...book };            // copies only the first level
draft.authors.push("New co-author");  // book.authors changed too
draft.meta.updated = Date.now();      // and book.meta as well

    Чому це погано. Spread копіює лише перший рівень, а вкладені масиви й об'єкти лишаються спільними. «Чернетка», яку збиралися скасувати, вже змінила оригінал, і кнопка «Скасувати» нічого не відновить.

    ✓ Добре 
    const draft = structuredClone(book);  // deep copy
// or update immutably at every level you change:
const updated = { ...book, authors: [...book.authors, "New co-author"] };

    Звички, завдяки яким код читається як опис наміру, а помилки з'являються одразу й у тому місці, де їх зроблено.

    const за замовчуванням

    Маленькі чисті функції, що повертають значення

    Функція, яка залежить лише від параметрів і повертає результат, працює однаково всюди: у консолі, у тесті, у рендері сторінки. Виведення й інші побічні ефекти зосереджені в одному місці (main, обробник події), тож його легко замінити.

    Змістовні імена й іменовані сталі

    Ім'я змінної каже, що в ній, ім'я функції — що вона робить. Число з бізнес-правила отримує ім'я, яке пояснює його зміст і живе в одному місці. Коментар «що робить код» стає непотрібним, лишаються коментарі «чому».

    const FREE_SHIPPING_FROM_IN_CENTS = 100000;

  return cartTotalInCents >= FREE_SHIPPING_FROM_IN_CENTS;
}

    Спершу функція відсікає некоректні випадки й повертає результат, а основний сценарій іде без вкладення. Кожна умова читається окремо, і її не треба тримати в голові до кінця функції.

    Незмінність даних

    Замість того щоб змінювати масив чи об'єкт, створюють новий з потрібними змінами. Тоді будь-яке значення можна безпечно передавати в інші функції, порівнювати «було — стало» й відкочувати. Цей принцип ляже в основу роботи зі станом у фронтенд-фреймворках.

    Метод масиву за наміром

    Назва методу — це документація. filter каже «відбираю», find — «шукаю один», some — «чи є хоч один». Правильний метод ще й ефективніший: find і some зупиняються на першому збігу, а filter(...).length > 0 проходить увесь масив.

    const hasOutOfStock = books.some((book) => !book.inStock);   // not filter(...).length > 0
const selected = books.find((book) => book.id === selectedId); // not filter(...)[0]
const titles = books.map((book) => book.title);               // not forEach + push

    Модулі з іменованими експортами й деструктуризація параметрів

    Кожен модуль відповідає за одну частину програми, а його публічний інтерфейс видно з export. Іменовані експорти коректно перейменовуються й шукаються редактором. Деструктуризація в параметрах показує, які поля потрібні функції, і робить виклик незалежним від порядку аргументів.
