CSS: основи, каскад, блокова модель

Після лекції ви зможете

  • пояснити, як браузер обирає одне значення властивості, коли на елемент претендують кілька правил: походження, шари, специфічність, порядок;
  • обчислити специфічність будь-якого селектора, зокрема з :is(), :where() і :has(), і передбачити, яке правило переможе;
  • писати селектори за атрибутами, станами й частинами елемента, не засмічуючи розмітку зайвими класами;
  • обирати одиниці під задачу й обґрунтувати, чому розмір шрифту задають у rem;
  • розрахувати розміри блока в обох режимах box-sizing і передбачити згортання вертикальних margin.

Теорія

1. Як CSS потрапляє на сторінку

HTML описує, що є на сторінці, а CSS — як воно виглядає. Правило CSS складається із селектора (кого стилізуємо) і блоку декларацій у фігурних дужках; кожна декларація — це пара «властивість: значення», завершена крапкою з комою.


/* selector */
.book-price {
  color: #1c2e57;     /* declaration: property + value */
  font-weight: 600;
}

Проблема. Уявімо каталог зі ста картками книжок. Якщо записати колір ціни прямо в атрибут style кожної картки, та сама декларація повториться сто разів, а зміна кольору перетвориться на пошук і заміну по всіх HTML-файлах.

Чому так. Атрибут style прив'язаний до одного конкретного елемента: його не можна перевикористати, у ньому не можна описати стан (наведення курсора, фокус) чи умову (медіазапит), і в каскаді він стоїть вище за всі правила з таблиць стилів автора, тож потім його важко перевизначити.

Рішення. Браузер вміє брати стилі з трьох місць. Зовнішній файл підключають елементом <link rel="stylesheet"> у <head>: браузер завантажує його один раз і кешує, тож усі сторінки сайту беруть стилі з кешу. Внутрішня таблиця стилів у елементі <style> діє лише на одній сторінці. Inline-стиль в атрибуті style діє лише на один елемент.


<head>
  <!-- external stylesheet: downloaded once, cached for every page -->
  <link rel="stylesheet" href="styles.css">

  <!-- internal stylesheet: applies to this page only -->
  <style>
    .catalog-intro { max-width: 60ch; }
  </style>
</head>
<body>
  <!-- inline style: applies to this one element only -->
  <p class="promo" style="color: #a8470f;">Знижка до неділі</p>
</body>

Є ще четвертий спосіб — правило @import усередині CSS-файлу. Воно має стояти на самому початку таблиці стилів (перед ним дозволені лише @charset і оголошення @layer), інакше браузер його проігнорує. Механізм його роботи пояснює, чому ним не зловживають: браузер дізнається про імпортований файл лише після того, як завантажив і розібрав батьківський, тому файли вантажаться ланцюжком, один за одним. Елементи <link> у HTML браузер бачить одразу й може завантажувати паралельно.


/* styles.css — @import must come first */
@import url("reset.css") layer(reset);
@import url("components.css") layer(components);

.catalog { padding: 1rem; }

Коли застосовувати. За замовчуванням — зовнішній файл через <link>. Елемент <style> доречний для окремої самодостатньої сторінки чи навчального прикладу. Inline-стилі в робочому коді залишайте хіба що для значень, які обчислює JavaScript під час роботи сторінки. @import має сенс, коли потрібно одразу розкласти імпортовані стилі по каскадних шарах (про шари — у розділі 3).

2. Селектори

Селектор — це умова, яку браузер перевіряє для кожного елемента DOM: якщо елемент їй відповідає, декларації правила беруть участь у каскаді для цього елемента. Базові селектори вибирають за іменем тегу, класом, ідентифікатором або будь-який елемент (*). Комбінатори поєднують селектори й описують зв'язок між елементами: пробіл — нащадок на будь-якій глибині, > — лише прямий дочірній елемент, + — наступний сусід, ~ — усі наступні сусіди з тим самим батьком.


article { }                     /* type: every <article> */
.book-card { }                  /* class */
#catalog { }                    /* id */
* { }                           /* universal */

.catalog .book-title { }        /* descendant, any depth */
.book-card > h3 { }             /* direct children only */
.book-title + .book-author { }  /* the very next sibling */
.book-title ~ p { }             /* every following sibling */

Механізм: браузер читає селектор справа наліво

Для .catalog .book-title браузер спочатку знаходить елементи з класом book-title (найправіша частина, так званий ключовий селектор), а потім для кожного піднімається вгору по предках і шукає .catalog. Тому довгі ланцюжки на кшталт body main ul li a змушують браузер робити більше перевірок: кожне посилання на сторінці проходить увесь ланцюжок предків.

Атрибутні селектори

Проблема. Стан картки вже записаний у розмітці — наприклад, data-status="sold-out", — але щоб візуально приглушити розпродану книжку, розробник додає ще й клас sold-out. Тепер ту саму інформацію треба синхронізувати у двох місцях.

Чому так. Здається, що CSS уміє чіплятися лише за класи. Насправді селектор у квадратних дужках порівнює рядкове значення будь-якого атрибута.

Рішення. [attr] перевіряє, що атрибут є; [attr="v"] — точний збіг; [attr~="v"] — одне зі слів у списку через пробіл; [attr|="v"] — значення дорівнює v або починається з v- (зручно для lang="uk-UA"); [attr^="v"] — починається з; [attr$="v"] — закінчується на; [attr*="v"] — містить підрядок. Прапорець i перед закривальною дужкою робить порівняння нечутливим до регістру.


/* state that is already in the markup */
.book-card[data-status="sold-out"] { opacity: 0.6; }

/* links to other sites and to PDF files (any letter case) */
a[href^="https://"] { text-decoration-thickness: 2px; }
a[href$=".pdf" i]::after { content: " (PDF)"; }

/* one word in a space-separated list: data-tags="new classic" */
.book-card[data-tags~="new"] { border-color: #e8772e; }

Коли застосовувати. Коли стилізуєте стан чи тип, що вже закодований атрибутом: disabled, type, aria-expanded, data-*, href. Специфічність атрибутного селектора така сама, як у класу.

Псевдокласи

Псевдоклас описує стан або положення елемента, яких немає в розмітці як атрибутів: курсор над елементом, фокус з клавіатури, позначений прапорець, порядковий номер серед сусідів. Браузер відстежує ці стани сам і перераховує стилі, щойно стан змінюється, — саме тому :hover працює без жодного JavaScript.


.book-card:hover { border-color: #1c2e57; }
.buy-button:focus-visible { outline: 3px solid #e8772e; outline-offset: 2px; }
.buy-button:disabled { cursor: not-allowed; }
.book-list > li:nth-child(odd) { background: #f4f6fa; }
.book-list > li:not(:last-child) { border-bottom: 1px solid #d3dae6; }
.filter input:checked + label { font-weight: 600; }

Зверніть увагу на різницю між :focus і :focus-visible. Перший спрацьовує за будь-якого фокусу, зокрема після кліку мишею. Другий — лише тоді, коли браузер вважає, що індикатор фокусу потрібен користувачеві, передусім під час навігації клавіатурою. Тому помітну рамку фокусу зручно вішати саме на :focus-visible: користувачі клавіатури бачать, де вони, а клік мишею не залишає зайвої обводки.

Псевдоелементи

Псевдоелемент вибирає не весь елемент, а його частину (::first-line, ::marker у пункті списку, ::placeholder у полі введення, ::selection — виділений текст) або створює згенерований вміст (::before, ::after). Пишуться з двома двокрапками; для чотирьох найстаріших (before, after, first-line, first-letter) браузери досі приймають і одну — це сумісність зі старим CSS 2.


.book-price::after { content: " грн"; }   /* no content — no pseudo-element */
.book-description::first-line { font-weight: 600; }
.book-list li::marker { color: #e8772e; }
.search-input::placeholder { color: #4a566d; }
::selection { background: #1c2e57; color: #ffffff; }

Обережно зі згенерованим вмістом

::before і ::after з'являються лише тоді, коли задано властивість content. Їхній текст не потрапляє в DOM, його не можна виділити й скопіювати, а програми зчитування екрана озвучують його по-різному. Тому псевдоелементи — для оформлення (іконки, розділювачі, одиниці), а не для змісту, без якого сторінка незрозуміла.

Групування: :is() і :where()

Проблема. Заголовки другого й третього рівня в каталозі та в бічній панелі мають однаковий міжрядковий інтервал, і селектор розростається до чотирьох повторів: .catalog h2, .catalog h3, .sidebar h2, .sidebar h3. Кожна нова комбінація множить кількість рядків.

Чому так. Звичайний список селекторів через кому — це просто кілька незалежних селекторів, і спільні частини в ньому доводиться повторювати.

Рішення. Функціональні псевдокласи :is() і :where() приймають список селекторів і збігаються з елементом, якщо збігся хоча б один із них. Різниця між ними — лише у специфічності: :is() отримує вагу свого найспецифічнішого аргументу, а :where() завжди має нульову вагу. Ще одна відмінність від звичайного списку: обидва мають «поблажливий» список аргументів. Якщо у звичайному списку через кому хоча б один селектор недійсний, браузер відкидає все правило; всередині :is() і :where() недійсний аргумент просто ігнорується.


/* before: every combination is spelled out */
.catalog h2, .catalog h3, .sidebar h2, .sidebar h3 { line-height: 1.2; }

/* after: specificity (0, 1, 1) */
:is(.catalog, .sidebar) :is(h2, h3) { line-height: 1.2; }

/* zero specificity: any later rule overrides it easily */
:where(.catalog, .sidebar) :where(h2, h3) { margin-top: 0; }

Коли застосовувати. :is() — щоб скоротити повторювані селектори, коли вага має бути звичайною. Пам'ятайте пастку: :is(#catalog, .shelf) .book-card має вагу ID навіть для елемента, що збігся через .shelf. :where() — для базових стилів і скидань, які будь-який компонентний клас має легко перевизначити.

Селектор «батька»: :has()

Проблема. Картку, всередині якої є бейдж «Новинка», треба обвести помаранчевою рамкою. CSS завжди вибирав елементи «вниз» по дереву, тож стилізувати картку залежно від її вмісту доводилося через додатковий клас, який ставив JavaScript або шаблонізатор.

Чому так. Звичайний селектор описує сам елемент і його предків, але не його нащадків чи наступних сусідів.

Рішення. :has() приймає відносний селектор і збігається з елементом, якщо відносно нього знайшовся хоча б один відповідник. Без комбінатора аргумент шукається серед нащадків на будь-якій глибині; з > — лише серед прямих дочірніх; з + чи ~ — серед наступних сусідів. Стилізується при цьому той елемент, що стоїть перед :has(). Специфічність — як у :is(): вага найспецифічнішого аргументу. Усі сучасні браузери підтримують :has() з кінця 2023 року.


/* a card that contains a badge anywhere inside */
.book-card:has(.badge) { border-color: #e8772e; }

/* a card whose cover image is a direct child */
.book-card:has(> img) { padding-top: 0; }

/* the hint of a field that contains an invalid input */
.form-field:has(input:invalid) .field-hint { color: #b42318; }

/* a title that is immediately followed by the author line */
.book-title:has(+ .book-author) { margin-bottom: 0.25rem; }

Коли застосовувати. Коли вигляд контейнера залежить від того, що в ньому лежить або що йде за ним: картка з обкладинкою і без, поле форми з помилкою, пункт меню з підменю. Якщо стан — це логіка застосунку (наприклад, «вибрано в кошик»), зрозуміліше відобразити його атрибутом чи класом на самому елементі.

3. Каскад і шари

Проблема. На заголовок картки претендують відразу кілька правил: стилі браузера за замовчуванням, базові стилі сайту, стилі компонента, утилітарний клас. Кожне задає свій color. Елемент може мати лише одне значення кожної властивості — яке саме?

Чому так. Стилі на сторінку надходять з різних джерел, і автори не домовляються між собою. Потрібен детермінований алгоритм, який за будь-якого набору правил дає той самий результат. Цей алгоритм і називається каскадом — від нього й літера C у назві CSS.

Рішення. Браузер збирає для елемента всі декларації однієї властивості й сортує їх за критеріями. Наступний критерій перевіряється лише тоді, коли попередній дав нічию:

  1. Походження й важливість. Стилі браузера (user-agent) → стилі користувача → стилі автора сайту. Для декларацій з !important порядок перевертається: важливе від браузера сильніше за важливе від автора.
  2. Прив'язка до елемента. Декларації з атрибута style перемагають декларації з правил із селекторами.
  3. Каскадні шари. Порядок шарів @layer; стилі поза шарами — окремий, найсильніший шар.
  4. Специфічність селектора (розділ 4).
  5. Порядок появи. Коли все інше рівне, перемагає декларація, що стоїть пізніше в коді.

Походження пояснює, звідки береться «стиль за замовчуванням». Коли ви не написали жодного рядка CSS, заголовок <h1> усе одно великий і жирний, а в <body> є зовнішній відступ 8px — це таблиця стилів браузера. Будь-яке ваше правило, навіть з найслабшим селектором, стоїть у каскаді вище й перевизначає її. Перевертання порядку для !important має людську причину: якщо користувач із поганим зором примусово задав собі великий шрифт і контрастні кольори, автор сайту не повинен мати змоги це скасувати.

Специфічність і порядок появи працюють лише всередині одного походження й одного шару. Саме тому !important «перемагає все»: він переносить декларацію на інший рівень першого критерію, і специфічність звичайних правил уже не має значення.

Каскадні шари @layer

Проблема. У проєкті є скидання стилів, базова типографіка, компоненти й утилітарні класи. Базове правило #catalog a (з ID) перемагає утиліту .text-accent, хоча за задумом утиліта має бути найсильнішою. Розробник або підвищує специфічність утиліти, або дописує !important — і починається «війна специфічностей».

Чому так. Без шарів порядок пріоритету між групами стилів визначають лише специфічність і порядок файлів, а обидва крихкі: випадковий ID чи перестановка <link> змінюють результат.

Рішення. Шари дають явний рівень пріоритету, що перевіряється раніше за специфічність. Порядок оголошується один раз на початку: шар, оголошений пізніше, перемагає ранішій незалежно від специфічності селекторів. Стилі, що не потрапили в жоден шар, вважаються сильнішими за всі шари. Для !important порядок перевертається, як і для походжень: важлива декларація з ранішого шару перемагає важливу з пізнішого, тож шар скидань може «захистити» критично важливе правило.


/* declare the order once, at the very top of the main stylesheet */
@layer reset, base, components, utilities;

@layer reset {
  [hidden] { display: none !important; }   /* protected: earliest layer wins for !important */
}

@layer base {
  #catalog a { color: #1c2e57; }            /* (1, 0, 1) */
}

@layer utilities {
  .text-accent { color: #a8470f; }          /* (0, 1, 0), but the later layer wins */
}

/* not in any layer: beats every layer */
.promo-banner a { color: inherit; }

Коли застосовувати. Щойно в проєкті більше одного джерела стилів: скидання, сторонні бібліотеки, ваші компоненти. Сторонній CSS можна одразу покласти в ранній шар через @import url("vendor.css") layer(vendor); — тоді будь-який ваш стиль у пізнішому шарі його перевизначить без жодного !important.

4. Специфічність

Проблема. Два правила в одному шарі задають колір заголовку картки: .catalog .book-title і #catalog h3. Друге стоїть раніше у файлі, але все одно перемагає. Чому порядок не спрацював?

Чому так. Каскад вважає, що точніший селектор виражає свідоміший намір автора, тож перевіряє специфічність раніше за порядок.

Рішення. Специфічність — це три лічильники, які записують як (A, B, C). У колонку A йдуть ідентифікатори. У колонку B — класи, атрибутні селектори й псевдокласи. У колонку C — селектори типів і псевдоелементи. Універсальний селектор *, комбінатори й :where() ваги не додають. :is(), :not() і :has() самі нічого не додають, але передають вагу свого найспецифічнішого аргументу.

Порівнюють колонки зліва направо, як слова в словнику: спершу A, і лише за рівності A — B, потім C. Колонки не «переповнюються»: (0, 11, 0) слабше за (1, 0, 0), бо перша ж колонка вирішує результат. Порядок появи в коді вступає в гру тільки тоді, коли всі три числа рівні.


h3                               /* (0, 0, 1) */
.book-title                      /* (0, 1, 0) */
.book-card h3                    /* (0, 1, 1) */
.book-card:hover .book-title     /* (0, 3, 0) */
a[href^="https://"]::after       /* (0, 1, 2) */
#catalog .book-card              /* (1, 1, 0) */
:where(#catalog) .book-card      /* (0, 1, 0) */
:is(#catalog, .shelf) .book-card /* (1, 1, 0) */
.book-card:has(> img.cover)      /* (0, 2, 1) */

Inline-стиль в атрибуті style часто описують як «специфічність (1, 0, 0, 0)». Зручніше тримати в голові, що він просто перемагає на ранішому кроці каскаду — прив'язці до елемента, — тому жоден селектор його не переб'є.

Коли застосовувати. Специфічність — не інструмент, яким треба «вигравати», а те, що варто тримати низькою й рівною. Якщо більшість правил мають вагу одного класу (0, 1, 0), то результат визначають шари й порядок, і стилі поводяться передбачувано. Перевірте власні селектори в калькуляторі специфічності.

5. Успадкування

Проблема. Без успадкування шрифт і колір тексту довелося б задавати кожному абзацу, заголовку, посиланню й пункту списку окремо.

Чому так. Частина властивостей за природою стосується тексту всередині блока, а не самого блока. Специфікація для кожної властивості вказує, чи вона успадковувана.

Рішення. Якщо для елемента жодне правило не задає успадковувану властивість, він бере обчислене значення цієї властивості від батька. Успадковуються переважно текстові властивості: color, усі font-*, line-height, letter-spacing, text-align, а також visibility, cursor, list-style. Не успадковуються властивості блока: margin, padding, border, background, width, height, display. Причина очевидна, якщо уявити протилежне: рамка картки, скопійована на кожен абзац і кожне посилання всередині неї.


.book-card {
  color: #1c2e57;               /* inherited by all text inside */
  font-family: "Onest", sans-serif;
  border: 1px solid #d3dae6;    /* not inherited */
  padding: 1rem;                /* not inherited */
}

/* form controls do not inherit the font by default: fix it explicitly */
button, input, select, textarea { font: inherit; }

Механізм: успадковане значення слабше за будь-яку декларацію

Успадкування працює лише тоді, коли для елемента немає жодної декларації цієї властивості. Навіть правило з нульовою специфічністю, наприклад * { color: #162033; }, — це декларація, яка прямо збігається з абзацом усередині картки. Тому вона перемагає колір, який абзац успадкував би від .book-card, хоча в .book-card специфічність вища. Специфічність порівнює правила, що збігаються з одним елементом; успадковане значення в цьому змаганні не бере участі.

Керувати успадкуванням можна ключовими словами, які підходять для будь-якої властивості. inherit примусово бере значення батька, навіть для неуспадковуваної властивості. initial ставить початкове значення зі специфікації (пастка: display: initial дає inline, а не block для div, бо «блоковість» задає таблиця стилів браузера, а не специфікація). unset поводиться як inherit для успадковуваних властивостей і як initial — для решти. revert відкочує до значення з попереднього походження, зазвичай до стилю браузера, а revert-layer — до значення з попереднього каскадного шару.

Успадковується саме обчислене значення, і це дає класичну пастку з line-height. Якщо задати його в em, браузер одразу перетворить його на пікселі на рівні батька й передасть нащадкам уже готове число. Множник без одиниць передається як множник, і кожен нащадок перераховує висоту рядка від свого шрифту.


.book-card { font-size: 1rem; line-height: 1.5em; }  /* computed 24px, inherited as 24px */
.book-card h3 { font-size: 2rem; }                    /* 32px text in 24px lines: lines overlap */

.book-card { line-height: 1.5; }                      /* the factor is inherited: h3 gets 48px */

Коли застосовувати. Типографіку задавайте якомога вище в дереві (на body чи на корені компонента) і дайте їй успадковуватися, а line-height пишіть без одиниць.

6. Одиниці вимірювання

Проблема. Та сама сторінка відкривається на телефоні шириною 360 пікселів і на моніторі на 2560, а частина користувачів збільшує типовий розмір шрифту в налаштуваннях браузера, бо так їм зручніше читати. Жорстко задані розміри поводяться погано в обох випадках.

Чому так. Абсолютна одиниця не знає нічого ні про екран, ні про вподобання користувача. Відносна одиниця прив'язана до чогось, що змінюється разом із контекстом.

Рішення. Кожна одиниця має свою точку відліку, і вибір одиниці — це вибір того, до чого прив'язати розмір.

px — «CSS-піксель», еталонна одиниця, а не фізична точка екрана: на дисплеях з високою щільністю один CSS-піксель займає кілька фізичних. Він не реагує на налаштування типового розміру шрифту, тож підходить для товщини рамок і тонких ліній.

rem — розмір шрифту кореневого елемента <html>. За замовчуванням у браузерах це 16px, але користувач може змінити його в налаштуваннях, і тоді весь інтерфейс у rem масштабується разом із ним. Значення не залежить від вкладеності: 1.25rem скрізь однакове.

em — розмір шрифту поточного елемента. Для самої властивості font-size це розмір шрифту батька, бо власного ще немає. Звідси ефект накопичення: список із font-size: 1.25em, вкладений у такий самий список, отримає 16 × 1,25 × 1,25 = 25px. Зате em ідеальна для відступів, які мають рости разом із текстом компонента: кнопка з padding: 0.5em 1em пропорційна за будь-якого розміру шрифту.

% — відсоток від чогось, що визначає сама властивість. Для width — від ширини блока-контейнера. Для padding і margin, навіть вертикальних, — теж від ширини контейнера, а не від висоти. Для font-size — від шрифту батька. Відсоткова height працює, лише якщо висота батька задана явно.

vw і vh — 1% ширини й висоти вікна перегляду. На мобільних браузерах панель адреси з'являється й ховається, тож «висота вікна» змінюється. 100vh там дорівнює найбільшому варіанту, і нижня частина блока опиняється під панеллю. Для цього існують одиниці svh (мінімальна висота), lvh (максимальна) і dvh (поточна, змінюється динамічно).


.book-card {
  width: 50%;                   /* of the containing block's width */
  padding: 1.5em;               /* grows with this card's own font size */
  border: 1px solid #d3dae6;    /* a hairline: px is fine */
}
.book-title { font-size: 1.25rem; }   /* 20px when the root is 16px */

.catalog-hero {
  min-height: 100vh;    /* fallback for older browsers */
  min-height: 100dvh;   /* the visible viewport height on mobile */
}

Коли застосовувати. rem — для розмірів шрифтів і загальної шкали відступів. em — для відступів, що мають масштабуватися разом із текстом конкретного компонента. % — для гнучкої ширини відносно контейнера. vw/dvh — для елементів, прив'язаних до екрана. px — для рамок, тіней і дрібних деталей, які не повинні рости разом зі шрифтом.

7. Кольори

Той самий колір у CSS можна записати кількома способами, і кожен зручний для свого. Іменовані кольори (navy, white) годяться для швидких експериментів. Шістнадцятковий запис #rrggbb (скорочено #rgb, з прозорістю — #rrggbbaa) звичний, бо його віддають графічні редактори. Функція rgb() приймає три канали від 0 до 255; у сучасному синтаксисі значення розділяють пробілами, а прозорість пишуть через скісну риску. Старий запис через коми, як-от rgba(0, 0, 0, 0.5), досі дійсний, але новий уніфікований для всіх колірних функцій.

hsl() описує колір відтінком (кут на колірному колі), насиченістю й світлістю, тож світліший варіант того самого кольору отримують зміною одного числа. Недолік — світлість у HSL не відповідає сприйняттю: жовтий і синій з однаковими 50% виглядають зовсім різними за яскравістю. oklch() будується на перцептивно рівномірному просторі: однакова світлість L виглядає однаково яскравою для будь-якого відтінку, тому палітри в ній передбачуваніші. Сучасні браузери підтримують oklch() з 2023 року.


.book-price {
  color: #1c2e57;                 /* hex */
  color: rgb(28 46 87);           /* the same colour, modern space-separated syntax */
  color: rgb(28 46 87 / 0.8);     /* 80% opacity */
  color: hsl(222 51% 23%);        /* hue, saturation, lightness */
  color: oklch(31% 0.078 264);    /* perceptual lightness, chroma, hue */
}

.badge {
  color: #a8470f;
  border: 2px solid currentColor; /* the border follows the text colour */
}

Ключове слово currentColor підставляє поточне значення color елемента. Рамка, іконка чи підкреслення, задані через нього, автоматично змінюють колір разом із текстом, наприклад у стані :hover. transparent — повністю прозорий колір.

Колір тексту має бути достатньо контрастним до фону. Критерій WCAG 2 рівня AA вимагає співвідношення контрасту щонайменше 4,5:1 для звичайного тексту й 3:1 для великого. Інструменти розробника в браузері показують контраст прямо в підказці до кольору в панелі стилів.

8. Типографіка

Проблема. Дизайнер обрав гарний шрифт, але в когось він не встановлений, у когось веб-шрифт ще не завантажився, а в когось у шрифті немає українських літер ї, є, ґ, і вони малюються іншим шрифтом посеред слова.

Чому так. font-family — це не один шрифт, а список кандидатів. Браузер іде по списку й для кожного символу бере перший доступний шрифт, у якому цей символ є.

Рішення. Задавайте стек шрифтів: бажаний шрифт, кілька системних з подібними пропорціями й наприкінці обов'язково загальне сімейство (sans-serif, serif, monospace), яке існує завжди. Веб-шрифт перевіряйте на підтримку кирилиці. Під час підключення з Google Fonts параметр display=swap відповідає дескриптору font-display: swap: текст одразу показується резервним шрифтом і підміняється, щойно веб-шрифт завантажиться, замість того щоб лишатися невидимим.


<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Onest:wght@400;700&display=swap">


body {
  font-family: "Onest", system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
  font-size: 1rem;
  line-height: 1.6;             /* unitless factor */
}
.book-title {
  font-size: 1.5rem;
  font-weight: 700;             /* 100–900; 400 = normal, 700 = bold */
  line-height: 1.2;             /* headings need tighter lines */
  letter-spacing: -0.01em;
}
.book-description { max-width: 65ch; }   /* comfortable line length */

Коли застосовувати. Для основного тексту — line-height близько 1,5–1,7, для заголовків — менше. Довжину рядка обмежуйте одиницею ch (ширина символу «0» поточного шрифту): рядки довжиною 45–75 символів читати найлегше. Будьте обережні зі скороченою властивістю font: вона скидає до початкових значень усі підвластивості, які ви не вказали, зокрема line-height.

9. Box model і box-sizing

Кожен елемент на сторінці браузер малює як прямокутник, що складається з чотирьох вкладених областей: контент, внутрішній відступ padding, рамка border і зовнішній відступ margin. Фон за замовчуванням заповнює контент, padding і область під рамкою; margin завжди прозорий і лише відштовхує сусідів. Скорочені записи читаються за годинниковою стрілкою від верху: padding: 8px 16px — вертикальні 8px і горизонтальні 16px; padding: 8px 16px 12px 4px — верх, право, низ, ліво.

Проблема. Картці задали width: 300px, padding: 20px і рамку 2px. На екрані вона займає 344 пікселі. Поле пошуку з width: 100% і внутрішніми відступами вилазить за край форми.

Чому так. Типове значення box-sizing: content-box означає, що width і height задають розмір лише області контенту, а padding і рамка додаються зовні: 300 + 2 × 20 + 2 × 2 = 344.

Рішення. З box-sizing: border-box ширина й висота задають розмір разом із padding і рамкою, а контент стискається під те, що лишилося: 300 − 40 − 4 = 256 пікселів контенту при 300 на екрані. Margin в обох режимах додається зовні.


.book-card {
  width: 300px;
  padding: 20px;
  border: 2px solid #1c2e57;
  margin: 16px;
}
/* content-box (default): on screen 300 + 2*20 + 2*2 = 344px */

.book-card { box-sizing: border-box; }
/* border-box: on screen 300px, content 300 - 40 - 4 = 256px */

Коли застосовувати. border-box вмикають глобально для всіх елементів і псевдоелементів на самому початку таблиці стилів (див. бест практики): так ширина, яку ви пишете, дорівнює ширині, яку бачите. Окремо варто запам'ятати outline: на відміну від рамки, він не входить у блокову модель і не займає місця, тому його зміна не зсуває сусідні елементи. Саме тому ним малюють індикатор фокусу. Покрутіть розміри в інтерактивній box model.

10. Властивість display

Властивість display визначає, як блок елемента поводиться серед сусідів. Типові значення задає таблиця стилів браузера: <div>, <p>, <article> — блокові, <span>, <a>, <strong> — рядкові. Змінюючи display, ви змінюєте лише відображення, семантика елемента лишається тією ж.

Блоковий елемент (block) починається з нового рядка й за замовчуванням розтягується на всю доступну ширину; до нього застосовуються width, height і відступи з усіх боків. Рядковий (inline) тече всередині тексту, як слово: width і height він ігнорує, вертикальні padding і рамка малюються, але не відсувають сусідні рядки, а вертикальні margin на розташування не впливають. inline-block поєднує обидва: стоїть у рядку поруч із текстом, але поважає розміри й усі відступи — типовий вибір для бейджа чи мітки в тексті.

display: none повністю прибирає елемент з макета й з дерева доступності: він не займає місця, і програма зчитування екрана його не озвучить. visibility: hidden робить елемент невидимим, але місце під нього лишається.


.book-meta { display: inline-block; padding: 0.25rem 0.5rem; }  /* in the text line, but boxes work */
.book-card[data-status="archived"] { display: none; }        /* gone from layout and accessibility tree */
.book-card.is-placeholder { visibility: hidden; }            /* invisible, keeps its space */

Сучасна специфікація описує display двома словами: зовнішнє відображення (як блок поводиться серед сусідів — block чи inline) і внутрішнє (як розкладаються його діти). Звичні однослівні значення — скорочення: block означає block flow, inline-block — inline flow-root. Внутрішні способи розкладки flex і grid розглянемо в наступних лекціях.

11. Згортання margin

Проблема. В описі книжки margin-bottom: 24px, у блоці ціни під ним — margin-top: 16px. Очікуєте проміжок 40px, а бачите 24. А заголовок із margin-top усередині картки без внутрішнього відступу раптом відсуває вниз усю картку, ніби margin «витік» назовні.

Чому так. У звичайному потоці вертикальні зовнішні відступи блокових елементів, які дотикаються, згортаються в один. Правило створене для тексту: абзаци з однаковими відступами зверху й знизу мають стояти на тій самій відстані один від одного, а не на подвійній. Результат — найбільший із відступів. Якщо один від'ємний, результат — сума найбільшого додатного й найменшого від'ємного; якщо обидва від'ємні — найменший із них.

Згортання трапляється у трьох ситуаціях. Перша — сусідні блоки: нижній margin одного й верхній наступного. Друга — батько й перший чи останній нащадок, якщо між їхніми відступами нічого немає: ні рамки, ні padding, ні рядкового вмісту, і батько не створює новий блоковий контекст форматування. Тоді margin нащадка опиняється зовні батька. Третя — порожній блок без висоти, padding і рамки: його верхній і нижній margin згортаються між собою.

Рішення. Згортання не відбувається для горизонтальних відступів, для елементів з float чи абсолютним позиціюванням і для дочірніх елементів flex- і grid-контейнерів. Щоб «замкнути» відступи дітей усередині батька, дайте батькові padding чи рамку або створіть новий блоковий контекст форматування через display: flow-root.


.book-description { margin-bottom: 24px; }
.book-price { margin-top: 16px; }
/* the gap between them: 24px, not 40px */

.book-card { padding: 1rem; }        /* padding separates parent and child margins */
.book-card { display: flow-root; }   /* a new block formatting context keeps child margins inside */

Коли застосовувати. Не боріться зі згортанням — обійдіть його домовленістю: задавайте вертикальні відступи лише в один бік (наприклад, тільки margin-bottom), тоді згортатися нічому. У flex- і grid-розкладці замість margin між елементами використовують властивість gap. Перевірте правило на живому прикладі.

Антипатерни

Кожен із цих прийомів «працює» в моменті, тому й поширений. Проблеми з'являються пізніше — коли стилі треба змінити, перевизначити або коли сторінкою користується хтось, кого автор не врахував.

!important для «лагодження» стилів

Погано


.book-price { color: #1c2e57; }

/* added later, "because it did not work" */
.sale .book-price { color: #b42318 !important; }
.book-card.featured .book-price { color: #11694a !important; }

Чому це погано. !important переносить декларацію на інший рівень каскаду, де звичайні правила вже не конкурують. Перебити її можна лише іншим !important — з вищою специфічністю або в ранішому шарі. Так починається ескалація: кожне наступне виправлення потребує ще одного !important, а справжня причина — конфлікт специфічності чи порядку — лишається непоміченою. Станові стилі (:hover, .is-active) без !important на такий елемент більше не діють.

Добре


/* find the winning rule in DevTools, then fix the order instead of forcing it */
@layer base, components, utilities;

@layer components {
  .book-price { color: #1c2e57; }
  .book-price.is-sale { color: #b42318; }   /* same layer, higher specificity */
}

ID-селектори для стилізації

Погано


#featured-book { border: 2px solid #e8772e; padding: 24px; }

/* now a sold-out state cannot win without another id or !important */
.book-card[data-status="sold-out"] { border-color: #d3dae6; }

Чому це погано. ID дає вагу (1, 0, 0), яку не переважить жодна кількість класів, тож будь-який варіант чи стан доведеться писати теж через ID або !important. До того ж ідентифікатор має бути унікальним на сторінці, отже стиль неможливо застосувати до другої такої картки: його доведеться дублювати.

Добре


.book-card.is-featured { border: 2px solid #e8772e; padding: 24px; }
.book-card[data-status="sold-out"] { border-color: #d3dae6; }  /* (0, 2, 0) — wins by order */

/* keep ids for anchors (href="#catalog"), label for="…" and ARIA references */

Inline-стилі

Погано


<article class="book-card" style="padding: 24px; border: 1px solid #ccc; color: #555;">
  <h3 style="font-size: 20px; margin: 0;">Кобзар</h3>
</article>

Чому це погано. Inline-декларації перемагають усі правила з таблиць стилів автора, тому змінити вигляд картки з CSS-файлу неможливо без !important. В атрибуті style не можна описати :hover, :focus-visible чи медіазапит, тож картка не може реагувати на стан і розмір екрана. Кожна картка несе власну копію стилів, і зміна дизайну — це редагування кожного HTML-файлу. Крім того, сувора політика безпеки вмісту (CSP) може взагалі заборонити inline-стилі.

Добре


<article class="book-card">
  <h3 class="book-title">Кобзар</h3>
</article>


.book-card { padding: 1.5rem; border: 1px solid #d3dae6; color: #4a566d; }
.book-title { font-size: 1.25rem; margin: 0; }

Довгі ланцюжки вкладених селекторів

Погано


body main .catalog ul li .book-card div h3 a { color: #1c2e57; }   /* (0, 2, 7) */

Чому це погано. Селектор повторює структуру HTML, тож будь-яка зміна розмітки — обгортка замість div, h2 замість h3, картка поза списком — мовчки вимикає стиль. Висока специфічність змушує кожне перевизначення бути ще довшим. Оскільки браузер перевіряє селектор справа наліво, для кожного посилання на сторінці він проходить увесь ланцюжок предків — зайва робота під час кожного перерахунку стилів.

Добре


.book-title-link { color: #1c2e57; }   /* (0, 1, 0): independent of the markup around it */

Фіксовані px для розміру шрифту

Погано


html { font-size: 14px; }
.book-title { font-size: 20px; }
.book-description { font-size: 13px; }

Чому це погано. Користувачі, яким важко читати дрібний текст, збільшують типовий розмір шрифту в налаштуваннях браузера. Розміри в пікселях цю настройку ігнорують: текст лишається 13px, і людині доводиться масштабувати всю сторінку разом із макетом. Значення 14px на html ламає це для всього сайту одразу, включно з усіма розмірами в rem.

Добре


/* leave the root font size to the user */
.book-title { font-size: 1.25rem; }         /* 20px at the default 16px */
.book-description { font-size: 0.875rem; }  /* 14px at the default, grows with the setting */

Ширина 100% без border-box

Погано


.search-input {
  width: 100%;
  padding: 12px;
  border: 2px solid #d3dae6;
}
/* on screen: 100% + 2*12px + 2*2px — 28px wider than the form */

Чому це погано. У режимі content-box padding і рамка додаються до 100%, тож поле виходить за межі форми й на вузькому екрані з'являється горизонтальна прокрутка. Розробник починає підбирати «магічні» значення на кшталт width: 93%, які ламаються за будь-якої зміни відступу чи ширини вікна.

Добре


*, *::before, *::after { box-sizing: border-box; }

.search-input { width: 100%; padding: 12px; border: 2px solid #d3dae6; }
/* exactly as wide as the form, padding and border included */

outline: none без заміни

Погано


.buy-button:focus { outline: none; }   /* "the blue ring looks ugly" */

Чому це погано. Людина, яка працює з клавіатури, орієнтується на сторінці лише за індикатором фокусу. Без нього вона не бачить, на якій кнопці стоїть, і може натиснути «Купити» не там. Критерій WCAG 2.4.7 «Видимий фокус» вимагає, щоб індикатор був помітним.

Добре


.buy-button:focus-visible {
  outline: 3px solid #e8772e;   /* outline takes no space: nothing shifts */
  outline-offset: 2px;
}

height: 100vh на мобільних

Погано


.catalog-hero { height: 100vh; }

Чому це погано. У мобільних браузерах 100vh дорівнює висоті вікна при схованій панелі адреси. Коли панель видно, нижня частина блока — часто разом із кнопкою дії — опиняється під нею. А жорстка height обрізає вміст, якщо користувач збільшить шрифт.

Добре


.catalog-hero {
  min-height: 100vh;    /* fallback */
  min-height: 100dvh;   /* follows the visible viewport; min- lets content grow */
}

Бест практики

box-sizing: border-box глобально

Ширина, яку ви пишете, дорівнює ширині, яку бачите: padding і рамка вже всередині. Розрахунки сіток і відсоткових колонок перестають вимагати арифметики. Селектор * не охоплює псевдоелементи, тому їх перелічують окремо. Правило ставлять на початок таблиці стилів — у шар скидань.


@layer reset {
  *, *::before, *::after { box-sizing: border-box; }
}

rem для типографіки

rem поважає налаштування розміру шрифту користувача й не накопичується у вкладених елементах, тому розмір у коді завжди означає одне й те саме. Для відступів, що мають рости разом із текстом конкретного компонента, доречна em.


.book-title { font-size: 1.5rem; }
.book-author { font-size: 1rem; }
.buy-button { font-size: 1rem; padding: 0.5em 1em; }   /* padding follows the button text */

Класи замість тегових селекторів

Тег описує зміст, а не вигляд. Правило h3 { … } зачепить кожен заголовок третього рівня на сайті, включно з тими, що в модальному вікні чи підвалі. А якщо заради структури документа заголовок картки стане h2, стиль зникне. Клас відв'язує вигляд від семантики: тегові селектори лишайте для базових стилів у ранньому шарі.


@layer base {
  h1, h2, h3 { line-height: 1.2; }           /* sensible defaults only */
}
@layer components {
  .book-title { font-size: 1.25rem; font-weight: 700; }   /* works on h2 and h3 alike */
}

Змістовні назви класів

Називайте клас за роллю елемента, а не за тим, як він зараз виглядає. Коли дизайн змінить червону ціну на помаранчеву, клас .red-bold почне брехати, і його доведеться перейменовувати в усій розмітці. Назва .book-price лишається правдивою за будь-якого дизайну, а стан можна виразити окремим класом з префіксом на кшталт is-.


<!-- describes the look: breaks on the next redesign -->
<span class="red-bold big">249 грн</span>

<!-- describes the role and the state -->
<span class="book-price is-sale">249 грн</span>

Порядок шарів оголошено одним рядком

Коли порядок шарів записаний явно на початку головного файлу, пріоритет груп стилів видно з першого рядка й він не залежить від порядку підключення файлів чи специфічності окремих селекторів. Сторонні стилі кладіть у ранній шар, щоб ваші правила перемагали без !important.


@layer reset, vendor, base, components, utilities;
@import url("vendor/slider.css") layer(vendor);

:where() для базових стилів

Базові стилі й скидання мають поступатися будь-якому компонентному класу. Обгорнуті в :where(), вони отримують нульову специфічність, тож їх перевизначає навіть один клас, де б він не стояв у файлі.


:where(h1, h2, h3, p) { margin-top: 0; }            /* (0, 0, 0) */
:where(.catalog) a { color: inherit; }              /* (0, 0, 1) */

.book-title { margin-top: 0.5rem; }                 /* wins with a single class */

line-height без одиниць

Множник без одиниць успадковується як множник, і кожен нащадок перераховує висоту рядка від власного шрифту. Значення в em чи px успадковується вже обчисленим, і великий заголовок усередині отримує тісні рядки, що налазять один на одний.


body { line-height: 1.6; }
.book-title { line-height: 1.2; }

Помітний фокус через :focus-visible

Індикатор фокусу потрібен тим, хто працює з клавіатури, і не заважає тим, хто клікає мишею. Малюйте його outline — він не займає місця й не зсуває макет. Колір індикатора має мати контраст щонайменше 3:1 до фону.


:where(a, button, input, select, textarea):focus-visible {
  outline: 3px solid #e8772e;
  outline-offset: 2px;
}

Квіз для самоперевірки

Дванадцять запитань на розуміння: частина з них показує код і питає, що відобразиться. Після кожної відповіді побачите пояснення, а в кінці — теми, до яких варто повернутися. Прогрес зберігається в цьому браузері.
