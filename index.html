Сучасна верстка: Flexbox і Grid

Flexbox розкладає елементи вздовж однієї осі. Grid одразу тримає рядки й колонки. Той самий набір карток нижче перемикається між моделями.

Питання лекції

  • головна і поперечна осі, вирівнювання, flex-grow, flex-shrink, flex-basis, перенесення, gap;
  • колонки й рядки Grid, fr, repeat, minmax, auto-fit і auto-fill;
  • іменовані області grid-template-areas, subgrid;
  • коли обирати одновимірну модель, а коли двовимірну.

Flexbox доречний для ряду кнопок, навігації, вирівнювання в одному напрямку. Grid доречний для каркаса сторінки і сітки карток, де важливі обидва виміри.

  grid-template-columns: repeat(auto-fit, minmax(16rem, 1fr));
  gap: 1rem;

Адаптивний дизайн і сучасні можливості CSS

Інтерфейс тримається на вузькому екрані, у великій типографіці й у темі, яку обрала система. Ця сторінка сама змінює кольори за prefers-color-scheme.

Питання лекції

  • mobile-first, метатег viewport, медіазапити і контейнерні запити;
  • адаптивні зображення: srcset і sizes;
  • плавна типографіка через clamp();
  • користувацькі властивості, світла і темна тема;
  • переходи, анімації, prefers-reduced-motion, вкладеність правил.

Практика

Клієнт

Колонки тут змінює контейнерний запит, а не ширина вікна.

CSS
:root { --ink: #1b1712; --bg: #efe7d6; }
@media (prefers-color-scheme: dark) {
  :root { --ink: #f4efe6; --bg: #12161c; }
}
h1 { font-size: clamp(2rem, 1.15rem + 2.6vw, 3.5rem); }
@media (prefers-reduced-motion: reduce) {
  .motion-dot { animation: none; }
}

export function average(grades) {
  const total = grades.reduce((sum, grade) => sum + grade, 0);
  return total / grades.length;
}

    HTTP, REST і Fetch API

    Відповідь — це статус і тіло. Екран під час запиту має один зрозумілий стан: завантаження, помилка, порожньо або дані.

    Питання лекції

    • методи HTTP, коди статусів, заголовки, JSON, принципи REST;
    • Fetch: метод, заголовки, тіло, response.ok;
    • мережева помилка і помилка статусу — різні випадки;
    • стани інтерфейсу: завантаження, помилка, порожній результат, дані;
    • CORS, вкладка Network, модуль API-клієнта.

      TypeScript: просунуті типи

      Точність типу зростає від фактів у коді: літерал дискримінанта, typeof, in, instanceof. Гілка, яка не повинна існувати, має тип never.

      Питання лекції

      • об’єднання, перетини, літеральні типи;
      • звуження, дискриміновані об’єднання, власні type guards, вичерпність через never;
      • generics і обмеження, Partial, Pick, Omit, Record, ReturnType;
      • satisfies, вибір між enum і об’єднанням літералів;
      • типізація DOM і відповідей API, tsconfig.

      Практика

      Фігура

      TypeScript
      type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "square":
      return shape.side ** 2;
    default: {
      const _exhaustive: never = shape;
      return _exhaustive;
    }
  }
}

      Якість клієнтського застосунку

      Якість видно в аудиті: сторінка керується з клавіатури, макет не стрибає, дія отримує відповідь, а дані людини не стають розміткою.

      • доступність за основними критеріями WCAG, аудит Lighthouse;
      • Core Web Vitals: LCP, INP, CLS;
      • розміри зображень, відкладене завантаження, defer і async;
      • XSS, екранування, ідея Content Security Policy;
      • структура застосунку і поділ на модулі.
      LCP
      Коли з’являється найбільший видимий вміст.
      INP
      Наскільки швидко інтерфейс відповідає на дію.
      CLS
      Чи зміщується макет під час завантаження.
