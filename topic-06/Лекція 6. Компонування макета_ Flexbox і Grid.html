Компонування макета: Flexbox і Grid

Два механізми розкладки, створені саме для інтерфейсів. Flexbox розподіляє простір уздовж однієї осі, Grid будує двовимірну сітку. Розберемо, як працює кожен, коли обирати який і як поєднувати їх у типових макетах.

Після лекції ви зможете

  • пояснити, чим Flexbox відрізняється від Grid, і обрати механізм під задачу;
  • керувати flex-контейнером: осі, напрямок, перенесення, вирівнювання, gap;
  • розрахувати розміри flex-елементів за flex-grow, flex-shrink, flex-basis і виправити переповнення через min-width;
  • будувати сітки з fr, minmax(), repeat(), auto-fit, іменованими областями й subgrid;
  • поєднувати Grid і Flexbox у типових макетах: сторінка з підвалом, holy grail, сітка карток, навігаційна панель, бічна панель;
  • налагоджувати розкладку через оверлеї Flexbox і Grid у DevTools.

Теорія

Наскрізний приклад — інтерфейс каталогу книжок: шапка з логотипом і пошуком, бічна панель фільтрів, сітка карток з обкладинкою, назвою, описом і кнопкою, підвал. Кожен його фрагмент — типова задача розкладки.

Звичайний потік і навіщо нові механізми

Без спеціальної розкладки браузер розставляє елементи у звичайному потоці. Блочні елементи йдуть один під одним і займають усю доступну ширину, рядкові — один за одним у рядку, як слова в тексті. Для статті цього досить. Для інтерфейсу — ні: картки мають стояти в ряд і мати однакову висоту, у шапці логотип ліворуч, а кнопки праворуч, бічна панель на телефоні має опинитися під контентом.

Півтора десятиліття розробники пристосовували для цього інструменти, створені для інших задач, і кожен мав побічні ефекти. Таблиці змішували розкладку із семантикою даних і плутали допоміжні технології. float придумали, щоб текст обтікав зображення: колонки на ньому вимагали «clearfix» і не вміли однакову висоту. В inline-block з'являлися проміжки від пробілів у HTML. Абсолютне позиціонування виривало елементи з потоку, і вони переставали зважати на сусідів.

CSS Flexible Box Layout і CSS Grid Layout спроєктовано саме для розкладки інтерфейсів, і обидва багато років мають статус Baseline Widely available. Вмикаються вони значенням display. Ця властивість має дві складові. Зовнішня визначає, як сам елемент поводиться серед сусідів (блочно чи рядково). Внутрішня визначає, як він розкладає своїх дітей. display: flex означає «блочний елемент із flex-розкладкою всередині», display: inline-flex — рядковий з тією самою розкладкою; так само працюють grid та inline-grid.

.toolbar { display: flex; }        /* block-level box, flex layout inside */
.badge   { display: inline-flex; } /* inline-level box, flex layout inside */
.catalog { display: grid; }        /* block-level box, grid layout inside */

Важливо, на кого діє контейнер. Flex- чи grid-елементами стають лише прямі нащадки, включно з текстом, який браузер загортає в анонімний елемент. Онуки залишаються у звичайному потоці свого батька, доки той сам не стане контейнером. На flex- і grid-елементах ігноруються float і vertical-align, а зовнішні відступи сусідів не «злипаються», як це буває у звичайному потоці.

Головна думка всієї лекції проста. Flexbox — одновимірний і «від вмісту»: він розкладає елементи вздовж однієї осі й дає кожному розмір з урахуванням вмісту. Grid — двовимірний і «від макета»: спершу описується сітка рядків і колонок, потім елементи розставляються в її комірки.

Коли це знадобиться. Щоразу, коли розкладка не є «текстом згори вниз». Перш ніж писати CSS, сформулюйте задачу: «в ряд з перенесенням» — це Flexbox, «рядки й колонки, вирівняні між собою» — Grid.

Flex-контейнер: осі, напрямок, перенесення, вирівнювання

Задача шапки каталогу звучить так: «логотип, меню й кнопка в один ряд, з проміжками, вирівняні по центру по вертикалі, а на вузькому екрані — з перенесенням». Описати її в пікселях і відступах крихко: будь-яка зміна тексту ламає розрахунок. Flexbox натомість описує намір.

Усе у Flexbox тримається на двох осях. Головна вісь (main axis) — напрямок, у якому йдуть елементи. Його задає flex-direction. Типове row — уздовж рядка тексту: для української чи англійської зліва направо, а для арабської справа наліво, бо напрямок залежить від мови документа. column — згори вниз. Варіанти row-reverse і column-reverse змінюють лише візуальний напрямок, але не порядок у DOM. Поперечна вісь (cross axis) перпендикулярна до головної. Коли ви змінюєте flex-direction, осі обмінюються ролями, а разом із ними змінюють напрям дії властивостей вирівнювання. Тому корисно думати не «горизонтально й вертикально», а «уздовж головної й уздовж поперечної».

justify-content розподіляє вільний простір, що лишився на головній осі після розміщення елементів. flex-start (типове значення) притискає елементи до початку, flex-end — до кінця, center — до центру. space-between рівно ділить простір між елементами, space-around дає кожному однаковий відступ з обох боків, тож по краях виходить половина, а space-evenly робить усі проміжки, включно з крайніми, однаковими. Якщо вільного простору немає, бо елементи розтягнулися через flex-grow, justify-content нічого не змінює.

align-items вирівнює елементи на поперечній осі. Типове значення stretch розтягує елементи на всю висоту рядка, тому flex-картки в ряд мають однакову висоту без жодних зусиль. flex-start, center і flex-end працюють так само, як для головної осі. baseline вирівнює елементи за базовою лінією першого рядка тексту, що зручно, коли поруч стоять заголовок і дрібний підпис. Окремий елемент може відступити від загального правила через align-self.

Типове flex-wrap: nowrap тримає всі елементи в одному рядку, навіть якщо їх доводиться стискати. wrap дозволяє переносити на наступний рядок, а wrap-reverse — на попередній. Кожен рядок розкладається незалежно: елементи різних рядків не вирівнюються в колонки, і саме в цьому ключова відмінність від Grid. Коли рядків кілька, align-content розподіляє самі рядки вздовж поперечної осі. Для одного рядка ця властивість нічого не робить.

Проміжки задають gap, row-gap і column-gap. Простір з'являється лише між елементами, а не по краях, тож не потрібні від'ємні відступи чи скидання margin в останнього елемента. Скорочення flex-flow поєднує flex-direction і flex-wrap.

<header class="site-header">
  <a class="site-header__logo" href="/">Book catalog</a>
  <nav class="site-header__nav" aria-label="Main">…</nav>
  <button class="site-header__cart" type="button">Cart</button>
</header>
.site-header {
  display: flex;
  flex-flow: row wrap;            /* flex-direction + flex-wrap */
  justify-content: space-between; /* free space on the main axis */
  align-items: center;            /* alignment on the cross axis */
  gap: 0.5rem 1.5rem;             /* row-gap column-gap */
}

Поряд із класичними flex-start і flex-end специфікація вирівнювання дає значення start і end. Вони прив'язані до напрямку письма, а не до flex-direction. Різниця помітна лише з -reverse: flex-start «перевертається» разом з напрямком, а start — ні.

Коли це знадобиться. Навігаційні панелі, панелі інструментів, групи кнопок, списки тегів, підвали карток — усе, де елементи йдуть в одному напрямку, а вирівнювання й проміжки мають бути гнучкими. Спробуйте кожне значення в пісочниці Flexbox.

Flex-елементи: як браузер ділить простір

«Поле пошуку займає все, що лишилося». «Три колонки ділять ширину у пропорції 1 : 2 : 1». «Логотип ніколи не стискається». Такі вимоги стосуються вже не контейнера, а розміру кожного елемента. Щоб передбачати результат, треба розуміти алгоритм, яким браузер ділить простір.

Спочатку кожен елемент отримує базовий розмір — flex-basis. Типове auto означає «візьми width (чи height для колонки), а якщо її немає, то розмір вмісту»; можна задати довжину, відсоток або 0. Потім браузер рахує вільний простір: розмір контейнера мінус суму базових розмірів і проміжків. Якщо вільний простір додатний, його ділять пропорційно до flex-grow (типово 0, тобто «не рости»). Якщо від'ємний, тобто елементи не вміщаються, нестачу розподіляють пропорційно до flex-shrink (типово 1), помноженого на базовий розмір: більші елементи віддають більше.

Приклад із ростом. Контейнер шириною 600px, проміжків немає. Три елементи мають flex-basis 100px, 200px і 100px та flex-grow 1, 2 і 1. Сума базових розмірів — 400px, вільно 200px. Частин росту разом 4, тож одна частина — 50px. Елементи отримують +50, +100 і +50 і стають 150px, 300px і 150px. Зверніть увагу: flex-grow ділить лише вільний простір, а не всю ширину. Тут друга колонка вийшла вдвічі ширшою лише тому, що й базові розміри відносяться як 2 : 1. Якби всі три мали flex-basis: 100px, вільні 300px розділилися б на 75, 150 і 75, і ширини склали б 175px, 250px і 175px — зовсім не 1 : 2 : 1.

.row { display: flex; width: 600px; }
.a { flex: 1 1 100px; } /* 100 + 50  = 150px */
.b { flex: 2 1 200px; } /* 200 + 100 = 300px */
.c { flex: 1 1 100px; } /* 100 + 50  = 150px */

Приклад зі стисненням. Контейнер 300px, два елементи з flex-basis: 200px: бракує 100px. Якщо flex-shrink у них 1 і 3, ваги стиснення дорівнюють 1 × 200 = 200 і 3 × 200 = 600. Перший віддає 100 × 200/800 = 25px, другий — 75px. Результат — 175px і 125px.

На практиці замість трьох окремих властивостей пишуть скорочення flex, і варто пам'ятати його ключові значення. flex: initial (те саме, що типове 0 1 auto) — не рости, стискатися можна, розмір від вмісту. flex: auto (1 1 auto) — рости від розміру вмісту. flex: none (0 0 auto) — жорсткий розмір за вмістом. flex: 1 (1 1 0%) — рости від нуля. Різниця між flex: 1 і flex: auto принципова. З базовим розміром 0 увесь простір ділиться порівну, і колонки мають однакову ширину незалежно від тексту. З auto ділиться лише залишок, тож елемент із довшим текстом буде ширшим.

Автоматичний мінімальний розмір. Flex-елемент має min-width: auto, і для нього це означає «не менше за мінімальну ширину вмісту». Довге слово, URL, блок <pre> чи таблиця не дадуть елементу стиснутися, і він вилізе за межі контейнера, хоча flex-shrink: 1 стоїть. Виправлення — дозволити стискання явно через min-width: 0 (для колонок — min-height: 0) і подбати про сам вміст, наприклад через overflow-wrap: anywhere.

.search-bar { display: flex; gap: 0.5rem; }
.search-bar__input  { flex: 1; min-width: 0; } /* takes the rest, allowed to shrink */
.search-bar__button { flex: none; }            /* keeps its content size */

Зовнішній відступ auto у flex-контейнері поглинає весь вільний простір у своєму напрямку, і робить це раніше за justify-content. Тому margin-inline-start: auto на кнопці «Кошик» відсуває її, а разом з нею й усі наступні елементи, до кінця рядка. margin: auto на єдиному елементі центрує його в обох напрямках.

order змінює лише візуальний порядок. Клавіша Tab, програми читання з екрана й виділення тексту йдуть за порядком у DOM. Якщо елемент переставлено так, що ці порядки розходяться, користувач клавіатури «стрибатиме» сторінкою. Тож змінюйте порядок у розмітці, а order лишайте для випадків, де послідовність не має значення.

Коли це знадобиться. Щоразу, коли елемент «не хоче» стискатися, колонки виходять різної ширини, хоча мали бути рівними, або простір розподіляється не так, як очікували. Порахуйте за алгоритмом або подивіться розміри в пісочниці, де вони виводяться для кожного елемента.

Grid: сітка, доріжки й одиниця fr

У каталозі картки стоять у рядах і стовпцях, і стовпці мають бути вирівняні між рядками. Flexbox з перенесенням розкладає кожен рядок окремо: якщо в останньому рядку дві картки, а не чотири, вони займуть інші місця, ніж ті, що вище. Потрібен механізм, який мислить рядками й колонками одночасно.

Grid починається з опису сітки. Її лінії (grid lines) нумеруються з 1 від початку й від'ємними числами від кінця. Простір між двома сусідніми лініями — доріжка (track), тобто рядок чи колонка. Перетин рядка й колонки — комірка, прямокутник з кількох комірок — область (area), а проміжки між доріжками задає той самий gap.

Доріжки описують властивості grid-template-columns і grid-template-rows. Розмір кожної доріжки може бути довжиною, відсотком, ключовим словом auto, min-content чи max-content, функцією minmax(min, max) чи fit-content() або значенням в одиницях fr. Одна fr — частка простору, що лишився після доріжок фіксованого розміру й проміжків. У контейнері шириною 800px без проміжків запис 200px 1fr 2fr спершу віддає 200px першій колонці, а решту 600px ділить у пропорції 1 : 2, тобто на 200px і 400px. repeat(3, 1fr) — коротший запис трьох однакових колонок.

Є тонкість, схожа на автоматичний мінімум flex-елементів. 1fr насправді означає minmax(auto, 1fr): колонка не стає вужчою за мінімальну ширину свого вмісту. Довгий URL у картці розширить свою колонку, і сітка вийде за межі контейнера. Запис minmax(0, 1fr) знімає цю нижню межу.

.catalog {
  display: grid;
  grid-template-columns: 200px 1fr 2fr;
  grid-auto-rows: minmax(8rem, auto);
  gap: 1rem;
}

.equal-columns {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr)); /* truly equal, even with long words */
}

Доріжки, описані в шаблоні, утворюють явну сітку. Якщо елементів більше, ніж комірок, браузер створює неявні доріжки. Їхній розмір задають grid-auto-rows і grid-auto-columns (типово auto). Напрямок автоматичного заповнення визначає grid-auto-flow: row (типово, рядок за рядком), column або з ключовим словом dense. Останнє заповнює «дірки», що лишилися від широких елементів, але змінює візуальний порядок відносно DOM з тими самими наслідками, що й order.

Коли це знадобиться. Каталоги, галереї, дашборди, каркас сторінки, форми з колонкою підписів — усе, де важлива двовимірна структура. Порівняйте різні шаблони колонок у пісочниці Grid: вона показує лінії й обчислені розміри доріжок.

Розміщення і вирівнювання в сітці

Без додаткових правил браузер розставляє елементи автоматично: по одному в комірку, в порядку DOM, рядок за рядком. Але в макеті часто потрібне інше: банер новинок на всю ширину, книжка тижня на дві колонки, шапка зверху над двома колонками. Grid дає три способи сказати, де стоїть елемент.

За лініями. grid-column: 1 / 3 означає «від лінії 1 до лінії 3», тобто дві колонки. grid-column: span 2 — дві колонки від того місця, куди елемент потрапив би автоматично. grid-column: 1 / -1 — від першої до останньої лінії, тобто на всю ширину. Від'ємні номери рахуються лише в явній сітці: неявні доріжки, створені автоматично, у цей відлік не потрапляють. Аналогічно працює grid-row, а скорочення grid-area: 1 / 1 / 3 / 4 задає по черзі лінії row-start, column-start, row-end і column-end.

За іменованими областями. grid-template-areas малює макет рядками тексту: кожен рядок у лапках — рядок сітки, кожне слово — комірка. Однакові імена утворюють область, крапка позначає порожню комірку. Область має бути прямокутником. Якщо ім'я утворює літеру «Г» або розірване на частини, оголошення недійсне повністю, і браузер ігнорує весь grid-template-areas. Елемент ставиться в область через grid-area: header. Бонус: кожна область автоматично створює іменовані лінії header-start і header-end.

.page {
  display: grid;
  grid-template-columns: 14rem minmax(0, 1fr);
  grid-template-areas:
    "header header"
    "filters main"
    "footer footer";
  gap: 1rem;
}
.page__header  { grid-area: header; }
.page__filters { grid-area: filters; }
.page__main    { grid-area: main; }
.page__footer  { grid-area: footer; }

За лініями з іменами. Лінії можна назвати прямо в шаблоні: grid-template-columns: [full-start] 1fr [content-start] minmax(0, 60rem) [content-end] 1fr [full-end]. Тоді grid-column: content поставить текст у центральну колонку, а grid-column: full — зображення на всю ширину. Так зручно будувати статті з «широкими» вставками.

.banner   { grid-column: 1 / -1; } /* full width of the explicit grid */
.featured { grid-column: span 2; } /* two columns from its auto-placed position */

/* two elements in the same cell overlap; the later one in the DOM is on top */
.cover,
.cover__caption { grid-area: 1 / 1; }
.cover__caption { align-self: end; z-index: 1; }

Останній приклад показує ще одну можливість, якої немає у Flexbox: накладання. Кілька елементів можуть займати ті самі комірки. Пізніший у DOM опиниться зверху, а z-index працює без position. Так кладуть підпис на обкладинку, не виводячи його з потоку.

Вирівнювання в Grid працює у двох площинах. Властивості з justify- діють уздовж рядкової осі (inline axis, для нашої мови — горизонтально), властивості з align- — уздовж блокової (block axis, вертикально). justify-items і align-items вирівнюють елементи всередині їхніх комірок. Типове значення stretch розтягує елемент на всю комірку. justify-self і align-self роблять те саме для окремого елемента. justify-content і align-content вирівнюють уже самі доріжки, коли їхня сума менша за контейнер, наприклад три колонки по 200px у контейнері 900px. Скорочення place-items: center дає найкоротший у CSS спосіб відцентрувати вміст в обох напрямках.

.empty-state {
  display: grid;
  place-items: center; /* align-items + justify-items */
  min-height: 20rem;
}

Коли це знадобиться. Іменовані області — для каркасу сторінки, де структуру зручно «бачити» в коді. Лінії й span — для окремих широких елементів у сітці карток. Накладання — для підписів, бейджів і декоративних шарів без абсолютного позиціонування.

Адаптивна сітка без медіазапитів: auto-fit, auto-fill, minmax

Скільки колонок має бути в каталозі? На телефоні одна, на планшеті дві, на моніторі чотири, а в бічній панелі — залежно від її ширини. Якщо описувати кожен випадок медіазапитом, правила множаться й прив'язуються до ширини вікна, а не до місця, де стоїть сітка.

Grid уміє сам рахувати кількість колонок. Запис repeat(auto-fill, minmax(16rem, 1fr)) означає: «створи стільки колонок завширшки щонайменше 16rem, скільки вміститься, а залишок поділи між ними порівну». Зі зміною ширини контейнера кількість колонок змінюється сама.

auto-fill і auto-fit відрізняються лише тоді, коли елементів менше, ніж уміщається колонок. auto-fill зберігає порожні доріжки, і дві картки на широкому екрані лишаються вузькими, а праворуч зяє порожнеча. auto-fit згортає порожні доріжки до нуля, і дві картки розтягуються на всю ширину. Для каталогу частіше потрібен auto-fit, а для сітки, де картки мають однаковий розмір незалежно від їхньої кількості, — auto-fill.

Лишається одна пастка. Якщо контейнер вужчий за мінімум у 16rem (наприклад, телефон на 320px з полями), колонка все одно буде 16rem і вилізе за край. Функція min(100%, 16rem) бере менше з двох значень: на вузькому екрані мінімумом стає вся доступна ширина.

.catalog {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr));
  gap: 1rem;
}

Схожого ефекту можна досягти Flexbox: flex-wrap: wrap плюс flex: 1 1 16rem на елементах. Різниця видно в останньому рядку. У Flexbox елементи останнього рядка розтягуються на всю його ширину: одна картка може стати втричі ширшою за решту. У Grid вони займають свої колонки. Обирайте за тим, яка поведінка потрібна.

Коли це знадобиться. У будь-якій колекції однотипних елементів: картки, галереї, плитки на дашборді. Порівняйте auto-fill і auto-fit з двома-трьома елементами в пісочниці Grid, змінюючи ширину контейнера.

Subgrid: вирівнювання всередині вкладених елементів

Сітка карток готова, але назви книжок мають різну довжину. В одній картці назва в один рядок, в іншій — у три, тож описи й кнопки «Детальніше» опиняються на різній висоті. Причина в тому, що кожна картка — окремий контейнер зі своєю розкладкою, і про сусідні картки вона нічого не знає.

Значення subgrid для grid-template-rows чи grid-template-columns змушує вкладену сітку не створювати власні доріжки, а використовувати доріжки батьківської. Картка займає три рядки батьківської сітки (grid-row: span 3) і розкладає свої назву, опис і кнопку по цих рядках. Висоту кожного рядка батьківська сітка визначає за найбільшим вмістом серед усіх карток ряду, тож назви, описи й кнопки вирівнюються між картками. Проміжки успадковуються від батька, але їх можна перевизначити. Нумерація ліній усередині subgrid починається з 1.

.catalog {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 14rem), 1fr));
  gap: 1rem;
}

.book-card {
  display: grid;
  grid-row: span 3;            /* title, description, button */
  grid-template-rows: subgrid; /* reuse the parent's row tracks */
  row-gap: 0.5rem;             /* overrides the inherited gap */
}

Subgrid підтримують усі основні браузери з вересня 2023 року, а з березня 2026-го він має статус Baseline Widely available. До його появи таку задачу розв'язували фіксованими висотами чи JavaScript, і обидва способи ламалися від зміни тексту.

Коли це знадобиться. Картки товарів чи книжок, тарифні плани, форми з вирівняними колонками підписів у різних секціях — скрізь, де вміст окремих блоків має вирівнюватися між ними. Подивіться приклад «Картки з subgrid» у галереї макетів.

Flexbox чи Grid і як їх поєднувати

Найчастіше запитання — «що краще?». Але ці механізми не конкурують: вони розв'язують різні задачі й найкраще працюють разом. Обрати допомагають три запитання.

Скільки вимірів? Якщо елементи йдуть в одному напрямку, а перенесення — лише спосіб вміститися, це Flexbox. Якщо важливі і рядки, і колонки — Grid. Хто визначає розмір: вміст чи макет? Теги різної довжини, кнопки за текстом, «скільки влізе» — Flexbox. Колонки заданих пропорцій, у які вміст має вписатися, — Grid. Чи мають елементи різних рядків стояти в колонки? Якщо так, Flexbox тут не впорається за визначенням, потрібен Grid.

Звідси типовий розподіл. Flexbox використовують для навігаційних панелей, панелей інструментів, груп кнопок, списків тегів, медіа-об'єкта (зображення і текст поруч) і для «відсунути елемент у кінець». Grid — для каркаса сторінки, сіток карток, галерей, форм з колонкою підписів і для накладання шарів.

Поєднання працює природно, бо кожен контейнер керує лише своїми прямими нащадками. Сторінка — це grid із шапкою, контентом і підвалом. Шапка всередині неї — flex-контейнер. Каталог у контенті — grid, а кожна картка — subgrid, підвал якої знову flex. Кожен рівень вирішує свою задачу й нічого не знає про розкладку вище чи нижче. Елемент із display: contents не створює власного блоку, і його діти беруть участь у розкладці батька напряму. Користуватися цим варто обережно: історично через це значення елементи губили свою семантику для допоміжних технологій, тож його не застосовують до кнопок, посилань і заголовків.

.page {                         /* Grid: page skeleton */
  display: grid;
  grid-template-rows: auto 1fr auto;
  min-height: 100dvh;
}
.site-header {                  /* Flexbox: one row of controls */
  display: flex;
  align-items: center;
  gap: 1rem;
}
.site-header__cart { margin-inline-start: auto; }
.catalog {                      /* Grid: two-dimensional collection */
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 14rem), 1fr));
  gap: 1rem;
}
.book-card__footer {            /* Flexbox inside a grid item */
  display: flex;
  justify-content: space-between;
  align-items: center;
}

Коли це знадобиться. На початку верстки будь-якого екрана. Розбийте макет на рівні — сторінка, секції, компоненти — і для кожного рівня окремо дайте відповідь на три запитання вище.

Типові макети інтерфейсу

Більшість екранів складено з невеликого набору перевірених схем. Знаючи їх, ви не винаходите розкладку щоразу, а впізнаєте задачу й берете відповідний рецепт. Кожну схему можна подивитися наживо, з кодом і зміною ширини, у галереї макетів.

Сторінка з підвалом унизу (sticky footer). Коли контенту мало, підвал не повинен висіти посеред екрана. Grid з рядками auto 1fr auto і min-height: 100dvh віддає весь залишок висоти контенту. Одиниця dvh враховує мобільні панелі браузера, що з'являються й ховаються. Звичайна vh дорівнює найбільшій висоті вікна, тож на телефоні підвал опинився б нижче краю екрана.

Holy grail — шапка, навігація, контент, бічна колонка й підвал. Класичний рецепт — іменовані області. На вузькому екрані все стоїть однією колонкою, на широкому медіазапит перевизначає лише grid-template-columns і grid-template-areas. Порядок у DOM лишається логічним, тож клавіатура й читачі екрана не страждають.

Сітка карток — repeat(auto-fit, minmax(min(100%, 14rem), 1fr)), а для вирівняного вмісту карток додається subgrid.

Навігаційна панель — Flexbox з align-items: center, gap і margin-inline-start: auto на групі дій. Із flex-wrap: wrap вона акуратно переноситься на вузькому екрані.

Бічна панель, що переноситься сама. Бічна панель має flex: 1 1 14rem, а основний вміст — flex: 999 1 0 разом із min-inline-size: 60%, і контейнер дозволяє перенесення. Доки контенту вистачає хоча б 60% ширини, вони стоять поруч, і контент забирає майже весь простір. Щойно місця менше, панель переноситься нагору чи вниз — без жодного медіазапиту.

Медіа-об'єкт — зображення поруч із текстом: обкладинка книжки й опис, аватар і коментар. Обкладинка має flex: none, текст — flex: 1 з min-width: 0, а align-items: flex-start не дає обкладинці розтягуватися на висоту тексту.

Центрування — display: grid; place-items: center на контейнері. Форма з колонкою підписів — Grid з grid-template-columns: max-content minmax(0, 1fr): підписи вирівнюються за найдовшим, а поля займають решту.

Коли це знадобиться. Під час верстки будь-якого макета від дизайнера. Розбийте екран на ці схеми, і половина рішень з'явиться ще до того, як ви напишете першу властивість.

Налагодження розкладки в DevTools

Сітка й flex-лінії невидимі, тож коли розкладка поводиться дивно, вгадувати її структуру з екрана важко. DevTools усіх основних браузерів уміють цю структуру показати.

У панелі Elements біля контейнерів стоять позначки flex і grid. Клік по позначці вмикає оверлей. Для Grid він показує лінії з номерами, позитивними й від'ємними, розміри доріжок, імена областей і заштриховані проміжки. Для Flexbox — межі контейнера, елементів і вільний простір. У Chrome на вкладці Layout зібрано всі сітки сторінки з перемикачами оверлеїв і налаштуваннями: показувати номери чи імена ліній, подовжувати лінії за межі сітки. Firefox має аналогічні Grid- і Flexbox-інспектори. Його Flexbox-інспектор ще й пояснює розмір кожного елемента: базовий розмір, на скільки елемент виріс чи стиснувся і чи впирається в мінімальний розмір.

У Chrome у панелі Styles поруч з display: flex чи display: grid є піктограма редактора. Вона дає змогу клацати по значеннях flex-direction, justify-content, align-items й інших і одразу бачити результат. Вкладка Computed показує фактичні розміри після розподілу простору.

Коли це знадобиться. Щоразу, коли елемент виявився не в тій комірці, колонка ширша, ніж очікували, або щось вилізло за край. Увімкніть оверлей і спершу подивіться на структуру, а вже потім правте CSS.

Інтерактивне демо

У пісочницях працює справжній CSS вашого браузера: змінюйте властивості, дивіться результат, обчислені розміри й код, який його дає. У галереї — готові макети, які можна стискати й розтягувати.

Антипатерни

Кожен із цих прийомів дає «правильну картинку» на одному екрані з одним текстом. Ламається він, щойно змінюється ширина вікна, довжина тексту чи спосіб навігації.

Колонки на float або inline-block

✗ Погано 
.book-card { float: left; width: 33.33%; }
.catalog::after { content: ""; display: table; clear: both; } /* clearfix */

.tag { display: inline-block; width: 25%; } /* + gaps from whitespace in HTML */

Чому це погано. float створювали для обтікання тексту, тож для колонок він вимагає «clearfix», не дає однакової висоти й не вміє вирівнювати по вертикалі. У inline-block пробіли й переноси рядків у HTML стають видимими проміжками, і чотири елементи по 25% не вміщаються в рядок. Будь-яка зміна вимагає перерахунку відсотків.

✓ Добре 
.catalog {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 14rem), 1fr));
  gap: 1rem;
}
.tags { display: flex; flex-wrap: wrap; gap: 0.5rem; }

Проміжки через margin замість gap

✗ Погано 
.tags { display: flex; flex-wrap: wrap; margin: -0.25rem; }
.tag { margin: 0.25rem; }
.toolbar__button { margin-right: 1rem; }
.toolbar__button:last-child { margin-right: 0; }

Чому це погано. Відступи потрапляють і на краї, тож їх доводиться компенсувати від'ємним margin контейнера або скидати в останнього елемента. З перенесенням «останній у рядку» — це не :last-child, тому праворуч лишаються зайві відступи. margin-right ще й прив'язаний до фізичного напрямку і ламається в мовах, що пишуться справа наліво.

✓ Добре 
.tags    { display: flex; flex-wrap: wrap; gap: 0.5rem; }
.toolbar { display: flex; gap: 1rem; }

Візуальна перестановка, що ламає порядок читання

✗ Погано 
/* DOM: description, price, "Buy" button */
.book-card__buy { order: -1; }          /* shown first */
.catalog { grid-auto-flow: row dense; } /* cards jump into holes */

Чому це погано. order, -reverse, dense і явне розміщення в Grid змінюють лише картинку. Фокус клавіатури, програми читання з екрана й виділення тексту йдуть за DOM. Користувач клавіатури натискає Tab і бачить, як фокус стрибає зверху вниз і назад, а незряча людина чує опис раніше, ніж кнопку, яку бачать усі інші.

✓ Добре 
<!-- Put elements in the DOM in the order people should read and focus them -->
<article class="book-card">
  <button class="book-card__buy" type="button">Buy</button>
  <p class="book-card__description">…</p>
</article>

Забути про автоматичний мінімальний розмір

✗ Погано 
.media { display: flex; gap: 1rem; }
.media__body { flex: 1; } /* contains a long URL or a <pre> block */

.layout { display: grid; grid-template-columns: 16rem 1fr; } /* 1fr = minmax(auto, 1fr) */

Чому це погано. Flex-елементи мають min-width: auto, а 1fr має нижню межу auto. В обох випадках елемент не стає вужчим за найдовше «неподільне» слово чи блок коду. На телефоні вся сторінка отримує горизонтальну прокрутку, хоча flex-shrink і fr начебто мали б стиснути колонку.

✓ Добре 
.media__body { flex: 1; min-width: 0; overflow-wrap: anywhere; }
.layout { display: grid; grid-template-columns: 16rem minmax(0, 1fr); }
.layout pre { overflow-x: auto; }

Відсоткові ширини разом із gap

✗ Погано 
.row { display: flex; flex-wrap: wrap; gap: 1rem; }
.col { width: 33.333%; } /* 3 × 33.333% + 2 × 1rem > 100% */

Чому це погано. Відсотки рахуються від ширини контейнера, а проміжки додаються зверху. Три «третини» плюс два проміжки не вміщаються, і третя колонка переноситься на новий рядок. Виправлення через calc((100% - 2rem) / 3) працює, але ламається, щойно змінюється кількість колонок чи розмір проміжку.

✓ Добре 
.row { display: grid; grid-template-columns: repeat(3, minmax(0, 1fr)); gap: 1rem; }
/* or with Flexbox: */
.col { flex: 1 1 0; min-width: 0; }

Фіксовані колонки й медіазапит на кожну ширину

✗ Погано 
.catalog { display: grid; grid-template-columns: 300px 300px 300px 300px; }
@media (max-width: 1280px) { .catalog { grid-template-columns: 300px 300px 300px; } }
@media (max-width: 960px)  { .catalog { grid-template-columns: 300px 300px; } }
@media (max-width: 640px)  { .catalog { grid-template-columns: 300px; } }

Чому це погано. Між контрольними точками сітка або вилазить за край, або лишає порожнечу праворуч. Медіазапити реагують на ширину вікна, а не на місце, де стоїть каталог: у бічній панелі чи модальному вікні правила не спрацюють. Кожна нова ширина — ще одне правило.

✓ Добре 
.catalog {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(100%, 18rem), 1fr));
  gap: 1rem;
}

height: 100vh для каркаса сторінки

✗ Погано 
.page { display: grid; grid-template-rows: auto 1fr auto; height: 100vh; }

Чому це погано. height обмежує сторінку висотою вікна: довгий контент вилізе за межі або змусить ставити overflow на внутрішні блоки, і з'явиться друга смуга прокрутки. На мобільних 100vh дорівнює висоті вікна без панелей браузера, тож підвал ховається під панеллю адреси.

✓ Добре 
.page { display: grid; grid-template-rows: auto 1fr auto; min-height: 100dvh; }

Обгортки-рядки всередині сітки

✗ Погано 
<div class="catalog">
  <div class="catalog__row"><article>…</article><article>…</article><article>…</article></div>
  <div class="catalog__row"><article>…</article><article>…</article></div>
</div>

Чому це погано. Це звичка часів float-сіток. Кількість карток у рядку зашито в HTML: на вузькому екрані її не змінити без JavaScript. Кожен рядок стає окремим контейнером, тож колонки різних рядків не вирівнюються, а сітка Grid отримує лише кілька «рядків-елементів» замість карток.

✓ Добре 
<div class="catalog">  <!-- one grid, the browser decides the rows -->
  <article>…</article><article>…</article><article>…</article>
  <article>…</article><article>…</article>
</div>

Бест практики

Звички, завдяки яким розкладка переживає зміну тексту, ширини екрана, мови й способу навігації без окремих виправлень.

Grid для каркаса, Flexbox для компонентів

Кожен рівень інтерфейсу отримує механізм під свою задачу: двовимірну структуру сторінки й колекцій — Grid, ряди елементів усередині компонентів — Flexbox. Код стає коротшим, а кожен контейнер відповідає лише за своїх прямих нащадків.

.page            { display: grid; grid-template-rows: auto 1fr auto; min-height: 100dvh; }
.site-header     { display: flex; align-items: center; gap: 1rem; }
.catalog         { display: grid; grid-template-columns: repeat(auto-fit, minmax(min(100%, 14rem), 1fr)); gap: 1rem; }
.book-card__tags { display: flex; flex-wrap: wrap; gap: 0.25rem; }

Проміжки через gap, напрямки — логічними властивостями

gap додає простір лише між елементами, а логічні властивості (margin-inline-start, padding-block, inset-inline-end) прив'язані до напрямку письма, а не до «лівого й правого». Та сама розкладка коректно працює і для української, і для арабської.

.site-header { display: flex; gap: 1rem; padding-inline: 1.5rem; }
.site-header__cart { margin-inline-start: auto; } /* pushes to the end of the line */

Внутрішня адаптивність замість контрольних точок

Сітка, яка сама рахує кількість колонок, і бічна панель, що сама переноситься, реагують на доступне місце, а не на ширину вікна. Тож вони однаково працюють і на всю сторінку, і в бічній колонці. Медіазапити лишаються для справжніх змін макета, а не для кожної кількості колонок.

.catalog { display: grid; grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr)); gap: 1rem; }

.with-sidebar          { display: flex; flex-wrap: wrap; gap: 1rem; }
.with-sidebar__sidebar { flex: 1 1 14rem; }
.with-sidebar__content { flex: 999 1 0; min-inline-size: 60%; }

Іменовані області для каркаса сторінки

Шаблон областей читається як схема макета прямо в коді. Щоб змінити макет на іншій ширині, досить перевизначити шаблон, не чіпаючи ні розмітки, ні правил окремих елементів. Порядок у DOM при цьому лишається логічним.

.page { display: grid; gap: 1rem; grid-template-areas: "header" "main" "filters" "footer"; }
@media (min-width: 60rem) {
  .page {
    grid-template-columns: 16rem minmax(0, 1fr);
    grid-template-areas: "header header" "filters main" "footer footer";
  }
}

Захист від переповнення за замовчуванням

Користувацький контент непередбачуваний: довгі назви, URL, коди замовлень. Якщо одразу писати minmax(0, 1fr) і min-width: 0 там, де колонка має стискатися, і давати тексту змогу переноситися, макет не «розірве» одне довге слово.

.layout { grid-template-columns: 16rem minmax(0, 1fr); }
.media__body { min-width: 0; }
.book-card__title { overflow-wrap: anywhere; }

Скорочення flex з усіма трьома значеннями

Окреме flex-grow: 1 лишає базовий розмір auto, а flex: 1 робить його нулем: результат помітно різний. Запис з усіма трьома значеннями, наприклад flex: 1 1 0 чи flex: 0 0 auto, показує намір явно, і читачу коду не треба згадувати типові значення.

.columns > * { flex: 1 1 0; }     /* equal shares of the whole row */
.tag         { flex: 0 0 auto; }  /* never grows or shrinks */
.search      { flex: 1 1 12rem; } /* starts at 12rem, takes the rest */

Subgrid для вирівняного вмісту карток

Замість фіксованих висот і обрізання тексту картки використовують рядки батьківської сітки. Заголовки, описи й кнопки вирівнюються між картками за найбільшим вмістом у ряду, а довгий заголовок нічого не ламає.

.book-card { display: grid; grid-row: span 3; grid-template-rows: subgrid; }

Налагоджувати з оверлеями, а не навмання

Оверлей показує реальну структуру: де проходять лінії, які доріжки неявні, скільки вільного простору лишилося у flex-рядку. Один погляд на нього зазвичай замінює десяток спроб «а якщо поставити 100%». Перевіряйте розкладку з довшим текстом і на вузькій ширині: саме там ховаються переповнення.
